## 3. 技术方案与边界

### 3.1 推荐技术选择

采用 Taro + React + TypeScript，使用小程序组件和平台 API。Taro 的 React API、组件、路由存在平台差异，不能直接复制 Next.js 页面；参见 [Taro React 说明](https://docs.taro.zone/docs/3.x/react-overall/)。

小程序 React/Taro 的确切版本在 T02 兼容性验证后锁定；不得因为网页使用 React 19，就假定当前 Taro 渲染器支持同一版本。小程序依赖独立安装，保留网页依赖版本。

建议最小目录方案：

~~~text
现有 app/、components/、hooks/       网页继续运行
现有 lib/tarot/、lib/agent/          优先复用纯数据/纯逻辑
现有 app/api/                      两端共用的后端
miniprogram/
  config/                          编译与环境配置
  src/
    pages/                         home、daily、library、history
    packages/reading/pages/        手动占卜
    packages/agent/pages/          Agent 对话
    packages/details/pages/        card、history 详情
    components/                    牌、牌阵、解读、确认框、状态组件
    adapters/                      网络、存储、生命周期适配
    features/                      reading、agent、daily 状态与编排
    styles/                        从网页令牌整理出的主题样式
    app.tsx
    app.config.ts
  tests/
  package.json
docs/tasks/
  plan.md
  todo.md
~~~

以上路径是计划路径，尚未创建实现。先通过编译别名/明确入口复用现有纯模块，优先沿用 lib/tarot/draw.ts，避免复制 useReading 中已有的抽牌实现。确有必要时，才提取共同模块；不先做整个仓库的 monorepo 改造。

根 tsconfig 当前匹配所有 ts/tsx，Vitest 也会发现新增目录：T02 必须隔离小程序源码/测试/产物的扫描范围，使根 Next.js 类型检查、lint、测试不误包含小程序端。任何排除只针对独立工程，不排除原网页文件来绕过错误。

### 3.2 平台适配

| 网页实现 | 小程序实现计划 |
|---|---|
| next/link、next/navigation | tab 页面切换、普通页面导航、返回栈；无上级栈时返回首页 |
| next/image | 小程序 Image + 按需加载、错误占位、配置化资源地址 |
| localStorage | Storage adapter；保留现有 schema/序列化语义，写入失败显式返回 |
| fetch / ReadableStream | Taro.request + enableChunked + RequestTask.onChunkReceived |
| AbortController / DOMException | 统一取消接口，映射到 RequestTask.abort；不依赖浏览器全局存在 |
| requestAnimationFrame / DOM | 小程序节点查询、动画和定时器；页面隐藏停止动画 |
| react-markdown | 小程序兼容 Markdown 解析与节点渲染，保留支持的格式与高亮 |
| window / document / 媒体查询 | 页面生命周期、窗口/安全区信息、键盘事件、移动端布局 |
| next/font/google | 合法可用字体资源及系统字体回退，不依赖 Next 字体运行时 |
| CSS / Tailwind 4 | 复用语义令牌生成适用样式；不默认整套网页 CSS 可直接编译 |

Taro 官方文档明确列出 chunked 请求、ArrayBuffer 分片回调与 abort 能力：[request](https://docs.taro.zone/docs/apis/network/request/)、[RequestTask](https://docs.taro.zone/docs/apis/network/request/RequestTask)。这些只证明接口可用，不能替代本项目代理链和真机兼容性验证。

### 3.3 环境与后端依赖

小程序公开配置仅包含 AppID、API 基地址、资源基地址和适用的运行参数；从构建环境/平台设置读取并验证，禁止硬编码本机地址、域名或密钥。所有模型密钥仍在服务端。

现有 API 不重写为云函数：
- GET /api/config：读取 available，用于全部 AI 入口加载、不可用与重试检查状态。
- POST /api/interpret：覆盖普通解读、followUp.decide/direct/with-extras、daily、agent.prompt。
- 不在小程序增加客户端模型密钥输入，不使用遗留 /api/models 作为用户设置功能。

真实联调前需要可访问的 HTTPS 服务和平台认可的域名配置。开发工具绕过域名校验不算验收。需验证代理是否缓冲 SSE、请求总时长和空闲时长、心跳能否抵达客户端；后端 maxDuration=300 不代表小程序请求一定能持续 300 秒。确需改变服务端协议时先记录证据和最小增量方案，不能静默降级为假流式。

现有后端是内存按 IP 限流，Agent 一次交互可能包含多个请求；真机验收须覆盖同网络下的 429，不能将无限重试作为恢复手段。账号鉴权或持久限流属于公开运营的后端决策，不伪装成已由前端解决。

## 4. 页面结构与导航

默认采用 4 个底部入口：首页、今日、牌典、轨迹。首页清晰提供“神谕对话”和“手动占卜”两个入口。流程页使用独立导航，不在输入区叠加底栏。

| 现有来源 | 小程序页面（逻辑名称） | 导航与状态 |
|---|---|---|
| app/page.tsx | home | 默认首页；今日卡预览、全部功能入口 |
| app/reading/page.tsx | reading | 同一页内推进流程；返回编辑、重开、返回首页/历史 |
| app/agent/page.tsx | agent | 自动流程和追问消息；新对话、停止、历史入口 |
| app/daily/page.tsx | daily | tab；本地日期、每日卡、札记、可回溯轨迹 |
| app/library/page.tsx | library | tab；六类筛选、分类列表、牌详情入口 |
| components/cards/CardDetail.tsx | card-detail | 将原弹层落实为独立详情页；按 cardId 加载 |
| app/history/page.tsx | history | tab；onShow 刷新、选择/批量删除/清空 |
| app/history/[id]/page.tsx | history-detail | 按 readingId 加载；完成追问展示、删除、返回 |

独立详情页属于交互形式适配，不增加新的业务能力。导航只传 ID/有效日期，不把完整牌库、敏感问题或历史正文放入 URL。非法参数展示明确空状态；tab 页不能依赖 URL query 传参，必要状态通过小型页面状态层传递。

## 6. 关键实现规则

### 6.1 AI 传输与渲染

网络层拆为平台 transport 与可复用的协议解析/错误归类；避免把 React state 和 wx 请求直接耦合。
- 分片首先进行有状态 UTF-8 解码，再按 SSE 事件边界组包；兼容 CRLF、尾部残片、注释心跳和多个事件同包。不能用每个 chunk 单独转字符串的方式解码中文。
- 保留 content、实际返回的 thinking、error、[DONE]、finish_reason=length 的语义；主流式缓冲完成/失败/取消时均 flush。
- 已确认纯函数可复用；含 DOMException、AbortSignal、fetch 的模块需适配后才能引入。
- 请求总超时、首包等待、空闲超时分别验证；心跳只重置适用的空闲判断，不能宣称能绕过平台总时长上限。
- 无正文时按分类进行有界自动重试；收到部分正文后不自动从头重试并追加。显式重生成保留原牌，新内容独立替换，不默默再抽一次牌。
- 截断和中途错误保留已显示内容并标记不完整；不能将错误分支渲染成遮蔽正文的整页错误。
- Markdown 先验证小程序节点兼容性，再选解析库并锁版本。处理未闭合标记、长段落、转义字符；不执行模型返回的 HTML。链接用平台可用方式呈现，不承诺任意外链都能打开。
- 只对新增内容节流更新，最终与累计文本一致；用户向上阅读时暂停自动滚底，回到底部再恢复。
- 取消按钮和网络中断分开显示；取消不会自动兜底发起新的模型请求。

### 6.2 状态与数据保存

传统流程沿用 question/spread/shuffle/draw/reveal/interpret 语义；追问按 deciding、awaiting-reveal、interpreting、done、error 实现实际路径。类型中 awaiting-draw 当前未实际使用，不凭类型名制造一个额外步骤。

小程序编排使用明确的当前请求 ID 和请求目标对象，避免依赖 state 刚更新后旧闭包读取。人工重试要能区分决策失败、揭牌未完成、解读失败，保持问题与已抽牌稳定。

历史与札记保持不同存储命名空间。50/60 的默认值来源于现代码，应汇总到产品策略配置，不在各页面重复数字。首次迁移保持默认行为；任何修改容量或淘汰策略均单独说明。
- 记录仅在符合保存条件时写入；重生成已有 readingId 时更新同一记录，首次失败/停止尚无 ID 时在成功后新建一条并保留该 ID；完成追问按现状写回。
- 页面内保留中断内容便于恢复；不把未完成内容伪装成成功历史。
- Agent 会话和每日 AI 仍是页面会话状态，不扩展为云端或跨重启恢复。
- 写入失败保留内存数据、展示失败与重试，不显示“已保存”；不得为了腾空间自动删除未授权的用户数据。
- 损坏记录逐项验证、可读记录仍可展示；不直接覆盖整个存储。格式版本用于本程序后续升级，不暗示能读取网页 localStorage。
- 札记切日时先保存原 dateKey 对应的内容，再加载新日期；清空仅删除目标日期。
- 小程序重新回前台时检查日期，更新“今日”标志；查看历史日期时不能强行切回今日。

### 6.3 页面隐藏与退出策略

本计划默认采用可预测的移动端策略：页面隐藏时终止本页活跃网络请求、停止动效与定时器；保存待写札记。返回同一存活页面显示“已停止/可重试”及已显示内容，不自动再次计费调用。退出销毁后保留已成功写入的历史和札记，不承诺恢复整个聊天。

新请求、切日期、重置、卸载都使旧 requestId 失效；旧回调和 finally 不可覆盖新请求的 loading、正文或日期。通过请求句柄隔离实现，不能只靠“调用 abort 应该就不会回调”的假设。

### 6.4 图像、样式和性能

牌图按配置化静态资源域名加载，优先直接复用现有服务的 /cards 路径；只有访问性能不达标才引入独立 CDN。首屏不下载全部 78 张，列表懒加载，当前牌阵适度预取，缓存只淘汰可再下载图像，不影响历史或札记。

T02 实测包体及分包开销，再锁定打包结构和资源预算。平台限额以执行当日官方文档/开发工具结果为准，不将旧配额写成当前事实。
- 保留卡牌 3:5 比例、翻面与逆位；复杂牌阵可滚动但不能遗漏阵位说明。
- 复用原设计令牌，不在小程序重新散落颜色/字号/间距。
- 手机无 hover，牌名、阵位、关键说明常驻或可点击；鼠标光晕改为轻量触摸反馈。
- 全量动效为目标；粒子密度和模糊效果依据目标真机测量调整，退化为静态背景时仍保留层次和所有交互。
- 不依赖远程字体才能读正文；降低动效时也必须能看到翻牌最终状态。
- 建议验收样本：窄屏、常规屏、大屏，iOS/Android 各一台及一台性能较弱设备；记录机型、微信/基础库版本和网络条件。
- 性能验收以首次基线确定的包体、首屏、长回复滚动与输入延迟目标为准；不预先捏造测量结果。

## 7. 现状疑点与迁移修复要求

以下是静态代码发现的风险，尚未执行复现测试，不能宣称已证实全部运行故障：
1. 传统追问 setState 后调用读取 followUps 闭包的函数，直接回复和揭牌后的解读启动需回归，避免新记录不可见。
2. 传统 retryFollowUp 仅在存在 decision 时执行，决策失败的“重试”需真正重新决策。
3. 每日札记卸载清除防抖，可能丢失最后一段输入；存储失败当前可能仍显示成功。
4. 每日旧请求 finally 可清除新日期请求的 loading；todayKey 留页跨日可能陈旧。
5. 错误归类依赖 DOMException；不能直接假定小程序具备该全局。
6. 普通和补牌使用随机 sort 洗牌，不保证均匀分布；本次先复用当前语义并验证单次抽牌无重复，不把算法统计性质写成已验证事实。更换随机算法若涉及共享网页行为，另行明确最小改动范围。
7. 补牌当前从完整牌库抽取，可能与首轮重复；本计划保持此规则，不擅自改为跨轮排重。
8. 首轮重新生成后已有追问仍保留，需在显示中避免把旧追问误认为基于新正文重生成。
9. ApiSettings 和 /api/models 遗留、首页牌阵数量文案、README 测试说明与代码不一致：计划按实际功能计数，不顺手删除无关文件。

迁移过程中新增回归测试来验证上述问题；只修复小程序实现或必须共享的直接依赖，不借迁移大范围改写网页。
