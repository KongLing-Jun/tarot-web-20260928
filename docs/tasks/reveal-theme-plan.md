## 5. 状态与操作契约

| 状态 | 内容 | 可用操作 | 禁止变化 |
| --- | --- | --- | --- |
| 未揭牌 | 逐张揭牌；已揭 0 / N；下一张为首牌位；全部牌背 | 顺序点牌、揭开下一张、全部揭牌、返回调整 | 不提前保存，不调用解读，不重新抽样 |
| 部分揭开 | 已揭 k / N；真实牌面、牌名与正逆位；强调下一张 | 顺序点牌、揭开下一张、全部揭牌；十字保留已有详情查看 | 不允许跳过顺序，不显示返回调整，不重复创建历史 |
| 全部揭开 | 牌面皆现；已揭 N / N；取消下一张强调 | 解读这些牌、重新抽牌；已有十字详情查看 | 不自动发起解读，不改变已抽出的牌 |
| 配置检查／服务不可用 | 保留全部牌面和既有状态提示 | 揭牌仍按现有行为；解读按 canUseApi 等条件禁用 | 不用固定值伪造服务可用，不丢弃结果 |
| 开始解读／重抽确认 | 沿用现有请求状态、按钮禁用和确认流程 | 正常完成、取消或重试按既有实现 | 不新增等待计时器、第二套状态机或接口调用 |

补充约束：
- “离开”仍到首页 `/`，不因为箭头外观改变成上一步。
- 返回调整保留已选牌；满额返回抽牌后保留现有“返回揭牌”行为。
- 一次点牌只对应一次既有揭牌动作；快速操作不得超出 N，不得重复保存或提交。
- 翻转动画只表达已有状态；不能借 animationend 再次派发揭牌。
- 单张牌在第一次揭开后直接进入全揭状态，无虚构中间步骤。

## 6. 实现决策

### 6.1 素材、字体和共享边界

- 优先复用狐狸、现有仪式牌背、桌布与星点素材。现有桌布若包含不适合本页的摆件且无法通过合理裁切匹配，才另生成无文字、无控件、无卡牌的揭牌专用背景；不覆盖原素材。
- 揭牌样式限定在自己的 CSS Module 或明确的阶段作用域；不全局修改 .btn-ink、.font-heading 或既有 celtic 布局。
- 首先复用 RitualScene 的能力；只有揭牌差异确实无法通过外部局部样式表达时，增加最小、默认兼容的参数。不得为了复用而改变洗牌／抽牌外观。
- TarotCard 优先透传 CardBack 已有外观类型；牌名与正逆位放在不参与旋转的区域，避免双份文字。其他调用点保留默认值。
- 核对字体子集覆盖所有按钮、牌名、六种牌阵和牌位名称；用户输入保留中文字体回退。新增字体字符时沿用现有构建脚本、来源与许可证。
- 桌布、狐狸不接收点击且对辅助技术隐藏；所有文案与按钮为真实 DOM。
- 不把生成图用作整个页面、透明按钮底图或生产数据。

### 6.2 布局

- 单张居中，三张主视口横排，五张根据可用宽度顺序换行；布局由真实牌位数量与既有牌阵定义驱动，不针对示例牌 ID 编写分支。
- 十字沿用当前手机和桌面位置定义、查看切换与详情；只调整本次范围内的视觉、间距和可访问操作。
- 同一牌阵在未揭／部分／全揭状态使用一致的牌位容器，预留足够牌名空间；长牌名允许换行，不能仅靠省略掩盖数据。
- 390 × 844 常规内容争取展示十张总览；短屏、长问题或文字放大时纵向滚动，不强行一屏、不以缩小点击目标换空间。
- 问题自然换行，不被狐狸覆盖；揭牌页没有现成全文入口，不直接复制共享头部的两行截断。长文本以纵向增长解决，不新增未经确认的弹窗。
- 底栏复用现有测量预留思路，依真实高度和安全区留足页面空间；若使用固定定位，最后一排、牌名、详情和错误提示均能滚到可见区域。
- 颜色、字体、间距与动效复用既有 token；必要的新样式值集中在揭牌作用域。服务地址、端口、资源输出目录等从配置／参数读取。

### 6.3 可访问性与动效

- 可操作控件至少 44 × 44 CSS 像素，焦点可见；不以微弱金光作为唯一状态提示。
- 卡牌可访问名称含牌位与是否可揭，未揭牌不得通过 alt 或 aria 提前泄露真实身份。
- Enter／Space 与点击行为一致；十字重叠牌仍可经既有按钮和按位置查看访问。不能产生嵌套 button 或吞掉已揭牌详情操作。
- “全部揭牌”消失后焦点有合理去向；只在用户动作使焦点节点消失时处理，不随每次渲染抢焦点。
- prefers-reduced-motion 下状态即时可见、流程可完成；保留现有动效能力，避免所有卡牌长期发光。
- 图片加载失败仍显示可读身份／重试等现有回退；仅已揭牌显示身份。
