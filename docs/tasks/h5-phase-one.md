# 微信小程序与 H5 共用页面：第一阶段体验调整

日期：2026-09-09
工作分支：`codex/integration-20260909`

## 范围

按本次确认，优化现有微信小程序 web-view 承载的 Next.js H5 页面。小程序 `miniprogram/pages/index/index.wxml` 通过 `web-view` 加载同一网站，两端共用页面、主题和业务流程。本次没有建立另一套 Taro 页面，也不对应原迁移计划中的 T01–T03。

## 已实现

| 用户体验 | 实现 |
| --- | --- |
| 首页入口 | 首屏突出“开始占卜”“今日一牌”；展开后选择自动推荐或自己选阵，底部保留牌典与轨迹。 |
| 手动流程 | 开始洗牌时确定牌面；可跳过动画、全部揭牌；返回提问仍保留草稿。 |
| 牌阵选择 | 用途在前，牌阵名称和牌数在后；六种牌阵全部可选。 |
| 解读阅读 | 提示词组织为核心解读、各牌说明、可采取的行动；完整三段内容完成后可展开牌面说明；流式与旧 Markdown 仍完整显示。 |
| 复杂牌阵 | 手动与 Agent 凯尔特十字共用牌阵图、位置列表和完整详情，展示牌名、正逆位与含义。 |
| 快捷追问 | 提供行动建议与牌面解释快捷草稿，自由输入保留。 |
| 等待和错误 | 区分选阵、补牌判断、解读阶段；错误与已收到正文同时显示；停止后可原牌重试；旧请求不能覆盖新请求。 |
| 每日札记 | 防抖之外，切日期、后台、离页时刷新保存；成功写入才显示已保存；失败提示与重试；当前会话保留失败草稿。窄屏日期轨迹改为可点击网格。 |
| 聊天滚动 | 上滑解除跟随，回到最新恢复；空会话不滚底；根据 visualViewport 和输入区高度适配软键盘。 |
| 动效 | 移动触摸设备静态背景、触摸反馈；隐藏时暂停背景；触摸不驱动鼠标视差；保留洗牌和翻牌。 |

## 操作约束

- “跳过洗牌动画”只结束当前动画，“全部揭牌”只增加揭开数量，二者均不重新抽牌。
- “重新解读（保留原牌）”复用本回合牌面；手动解读更新同一条历史，不复制记录。
- “重新抽牌”有明确确认。手动流程保留问题与牌阵并进入新抽取；Agent 保留旧回合并重新选阵、抽牌。
- 尚未抽到牌的失败不能承诺保留原牌，显示“重试选阵与抽牌”。
- 追问决策失败重试补牌判断；已经形成补牌结果则仅重试回答，保留补牌。
- 新解读未收到正文前保留上一版正文；取消同步保留缓冲中的文字。

## 验证

- `npm test`：17 个文件、116 项测试通过。
- `npm run lint`：通过。
- `npx tsc --noEmit`：通过。
- `npm run build`：通过，完成全部 13 个页面的预渲染/路由构建。
- 浏览器实际执行：返回保留问题、凯尔特选阵、启动与跳过洗牌、逐张/全部揭牌、切换图与位置详情。
- 390px 与 320px 小屏检查：首页、Agent、手动流程；每日页 320px 检测并修复横向溢出，文档宽度与可用视口宽度一致。
- 回归覆盖：原牌和历史 ID 复用、重复点击、请求取消/过期回调、首字前失败、追问决策重试、札记写入失败与生命周期保存、滚动跟随、背景暂停。

## 验证边界

- 浏览器验证不能替代微信 iOS/Android 真机验收；真机软键盘、web-view 后台与强制退出事件仍需设备验证。
- 写入失败的札记在当前页面会话保留并提供重试；浏览器或微信进程被强制结束后，不能保证恢复尚未写入的内存草稿。
- AI 流式与错误分支用测试替身验证，本轮没有额外发起真实模型请求。
- 本地修改未提交或推送；用户既有配置与架构文档保留。
