# 洗牌舞台消失与底部空白修复

用户截图中牌桌、牌堆消失，说明与操作区上移，底部出现大片空白。此问题由上一轮单屏布局的高度兼容处理遗漏引入。

## 根因证据

`RitualScene.module.css` 原写法在同一规则中依次声明 `height: 100vh`、`height: 100dvh`。检查实际生产 CSS，发现前一条被优化移除，仅剩 `100dvh`。容器一旦不识别该单位就失去确定高度，内部 flex 舞台高度变成 0；页面底部露出 body 背景。

项目 `postcss.config.mjs` 记录微信开发者工具 NW.js 0.54.1 使用 Chromium 91。动态视口单位由 Chrome 108 引入，参见 [Chrome 官方说明](https://developer.chrome.com/blog/chrome-108-beta)。本次没有直接读取用户当前模拟器内核版本，因此不将项目配置等同于真机测量。

验证在构建后的样式上模拟“不支持新视口单位”的条件：移除不支持的声明与对应 supports 分支，再用真实 Chrome 渲染。修复前实际测得 `stageHeight: 0, cardWidth: 0, cardHeight: 0`，产生与用户截图一致的布局。[修复前后对照](comparison.png)左为失败复现，右为同尺寸修复结果。

## 修改

只修改两阶段共用的高度规则：基础规则保持 `height: 100vh`，`height: 100dvh` 放入独立 `@supports (height: 100dvh)`。检查最终生产 CSS，基础声明和条件增强均保留，避免前者再次被优化合并。洗牌、抽牌共用此修复；未调整随机结果、业务流程或其他页面。

新增编译回归测试，要求真正经过项目 PostCSS 链后仍保留无条件 vh 回退。浏览器验收新增场景高度等于视口，以及牌桌、牌堆实际具有可见尺寸的断言；仅验证按钮可见不足以证明页面完整。

## 验证

- 新增 CSS 编译测试先失败，修复后 5 文件、38 项相关测试通过。
- 新增浏览器图像可见性断言先复现失败，修复后通过。
- [不支持新视口单位条件下的浏览器结果](legacy/results.json)：七种尺寸，包含洗牌前/中/后、抽牌、辅助操作与键盘检查。
- [现代浏览器正常样式结果](modern/results.json)：390 × 744 通过。
- 生产构建（含 TypeScript）、相关 ESLint、diff 空白检查通过；实际产物检查确认 `100vh` 回退未被删除。
