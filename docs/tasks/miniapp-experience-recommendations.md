# 月映卡语小程序整体体验优化建议

日期：2026-09-10。依据当前 React / Next.js 页面、web-view 接入方式和用户确认的目标。

## 产品目标

让用户说清处境与感受，借牌义获得分析视角，形成能尝试的行动，再根据现实反馈调整。情绪来自用户表达和确认，牌面不替代用户事实；有效性以理解是否准确、行动是否清楚、现实反馈是否有帮助来判断。

以下建议记录 2026-09-10 当时的产品方向，不作为当前实现清单。后续体验改动见[体验优化交付](./experience-optimization.md)，手机手势和当前修复见[2026-09-11 集成记录](./integration-20260911.md)；未有交付证据的建议仍不代表已实现。

## 优先清单

| 优先级 | 环节 | 建议 | 实施边界 |
| --- | --- | --- | --- |
| P0 | 首页 | 主入口直达“说说正在困扰你的事”；自主选阵作为次入口；减少品牌装饰和每日牌图的首屏占高。 | 复用现有对话和手动页面，前端调整即可。 |
| P0 | 提问 | 用可跳过的“发生了什么 / 最在意什么 / 想获得什么帮助”引导；示例问题先填草稿，再由用户修改发送。 | 不把示例自动当成真实经历；沿用当前问题输入。 |
| P0 | 情绪 | 提供可选感受标签、自由补充和“不确定”，允许用户纠正理解。 | 先作为可编辑提问草稿；独立保存情绪需要另行扩展接口、校验和存储。 |
| P0 | 解读 | 保留现有“事情怎么看 → 可以怎么做 → 折叠的牌义依据”；减少重复标题和术语。 | 当前已具备分层和追问上下文，勿重新实现一套并行解读结构。 |
| P0 | 纠偏 | 增加“这个理解不符合 / 补充情况 / 具体怎么做”快捷追问，先填草稿。 | 复用现有牌面和对话历史；用户修正优先，不自动重抽。 |
| P1 | 行动 | 给出一个当下能尝试的小行动，并说明作用与观察点；背景不足时先明确缺少什么。 | 先调整提示词和质量评阅；不要用前端固定模板伪造分析结果。 |
| P1 | 复盘 | 历史支持继续聊同一件事、记录尝试和现实进展。 | 恢复原问题、牌面和追问；独立行动和反馈记录需要扩展数据结构。 |
| P1 | 移动阅读 | 清晰的中文正文、装饰字体集中于标题；抽牌保留仪式感；保护键盘、安全区和用户主动滚动。 | 扩展现有移动样式，保持现有流式停止跟随与回到最新功能。 |

## 后续验收方法

- 新用户无需理解牌阵即可开始描述问题。
- 不选情绪标签也能完成流程，未确认的情绪和他人心理不被写成事实。
- 用户能复述当前分析、下一步小行动和需要观察的反馈。
- 补充或纠正背景后，回答承接新事实，保留本次牌面。
- 从历史继续时，可恢复相同问题和已完成追问，而不是静默开启另一轮抽牌。
- 在实际微信客户端验证键盘、长文本、展开牌义及前后台恢复，不能用桌面截图替代真机结论。
