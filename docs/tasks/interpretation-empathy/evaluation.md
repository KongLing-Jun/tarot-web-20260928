# 内容质量评估记录

日期：2026-09-15。模型：现有配置的 `deepseek-v4-flash`。输入来源全部为 synthetic，真实用户样本数为 0。未导出生产聊天。

## 方法与证据

使用 17 条固定输入覆盖六牌阵、事实/情绪纠正、已尝试建议、目标正反对照、失败回合补充、倾诉和每日。每轮使用相同问题、历史、牌面、正逆位及同一模型；超时 180000 ms、输出预算 65536 均来自已有私有运行配置。每例每版本调用一次，无挑选最佳结果；中间试验也保留。

本机完整证据位于 `docs/verification/interpretation-empathy/`（Git 忽略目录），各目录包含 `manifest.json`、逐例 Prompt/输出与结果。Manifest 记录 Prompt SHA-256、基线提交 `04852b4`、工作区状态、模型、日期和预算；未记录密钥或连接地址。

| 目录 | 版本与用途 |
| --- | --- |
| `baseline` / `baseline-run` | 改写前冻结的 17 条提示词及实际输出 |
| `stage1` / `stage1-run` | 保留强制三段的第一阶段；生成 6 个风险场景 |
| `candidate` / `candidate-run` | 首次可选章节候选；17 条实际输出与匿名对照 |
| `blind` / `blind-key.json` | 每例随机交换 A/B；映射与评审输入分开 |
| `reviewer-one.json` / `reviewer-two.json` | 两个独立 AI 评审的逐例评分、原句证据和偏好 |
| `final` / `final-run` | 修正评审暴露的问题后，再冻结最终提示词并复测全部 17 条 |
| `final-review-one.json` / `final-review-two.json` | 知晓最终版本的两份独立 AI 复核，逐例保留问题引文 |

生成评估为非流式请求，未经过微信登录及本地流式代理；首 token 时延未知。确定性质量使用运行时校验器，旧版输出的检查结果不能反推旧版前端行为。

## 第一阶段发现及修正

6/6 得到完整有效正文，但共情与事实边界未达标。例如情绪纠正场景仍写“你此前选择岗位时较依赖内在判断、信息筛选和直觉”；不复合场景通过恋人牌推断用户仍有情感牵连。倾诉场景虽然不列任务，仍被强制安排“可采取的行动”章节，反复讲解同一结论。

据此增加过去牌位的正反例、明确旧 AI 回答不作为事实，并接入可选行动与直接追问省略重复牌义。保留所有中间结果，没有把失败试验移出记录。

## 可选章节候选版的 AI 盲评

两位评审均逐例阅读匿名输入及 A/B 回答，不读取版本映射或另一位结果。评分锚点沿用方案，严重错误须引用原文。它们是模型辅助评审，不是两位真人，也不是用户满意度研究。

| 评审 | 偏好候选 | 偏好旧版 | 平局 | 候选偏好率（全部 17 例为分母） |
| --- | --- | --- | --- | --- |
| AI 评审一 | 14 | 3 | 0 | 82.35% |
| AI 评审二 | 14 | 2 | 1 | 82.35% |

不能将以上结果写成最终版或真实用户的偏好率。两份评审对自然表达的打分差异明显，且依然认为牌义、边界声明和行动理由重复较多。候选的 17/17 结构检查无异常，也未阻止下面的语义问题：

- 两位均指出倾诉样本把“投了三个月简历没有结果”改写成“没有回音”，补写未知经历。该样本虽更尊重不做任务的诉求，事实错误仍需单列。
- 一位进一步指出二择一样本把“起薪较低、无额外缓冲”推导为“三个月储备会很快消耗”，缺少收入是否覆盖实际开支的必要条件。另一位将此记为分析不足，两者分歧保留。
- 旧版二择一还存在把两工作收入差当生活现金缺口的分析错误；不因它未归入原五种事实错误而忽略。

因此候选虽然得到较高辅助偏好，**未满足零严重错误门槛**。最终提示词进一步保持用户原话范围，明确结果/回应/面试不等同，区分相对收入变化与实际收支，并把每张牌的说明标为词典解释而非用户事实。

## 最终代码的语义复核结论

两位 AI 评审均逐例阅读最终 17 条输入/输出并核对引文。这次知晓版本，不是盲评。评审一判定 15/17 无实质错误，评审二判定 14/17；“无实质错误”不代表满分，也不等于共情达标。

双方一致指出两个仍需解决的样本：

1. `timeline`：没有技术水平、样片、曝光或客户反馈资料，却将尚无付费客户归因为可见度和信任不足，并排除技术作为首要问题。模型仍会把一种合理待核对假设写成确定诊断。
2. `listen-only`：结尾将招聘流程、岗位要求、专业意见等未说明的外部条件写成“这些外部条件目前尚未发生”，混淆未知与未发生。前面修复的“没结果 ≠ 没回应”没有解决全部事实范围问题。

对 `two-options` 存在分歧：收入差与现金缺口的计算错误已修复，但最终输出用“持续负余额”直接认定 B 的财务前提不成立，未结合缺口大小、储备覆盖期及过渡期。评审一列 warning，评审二列 error；保留分歧并作为需要改善的建议判断，不用低等级标记掩盖它。

**验收结论：工程与展示兼容通过；内容质量不予全部通过。** 最终合成集仍未满足零严重错误要求，真实样本验收也缺少输入。没有为让结果通过而删除案例、隐藏结构警告、降低门槛或上线自动重写。当前改动保留在工作区，可审查；不能把它作为内容质量已经彻底解决的证据。

下一轮内容工作应围绕“先核对原因再诊断、未知不等于不存在、建议结论与必要前提一致”做对照。已有多轮 Prompt 修正后仍出现这类缺陷，继续追加反例可能增加重复与模板感；在新增生成调用或替换模型前，应先用真实不满意样本确认问题分布，并以相同样本比较方案的效果、耗时和用量。

## 最终验收边界

工程验收见 [delivery.md](delivery.md)。真实匿名样本与真人盲评尚未取得，所以原计划的“30 条真实样本、真实偏好至少 70%、零严重错误”仍不能标记通过。合成试验能帮助发现缺陷和比较版本，不能证明线上所有回答均能共情或不再推断过度。

下一步应使用用户实际不满意的原问题与解读进行同牌复核，优先确认长篇牌义是否仍干扰陪伴感、行动是否真的只有一个当前步骤，以及事实范围有没有被缩窄。不要在没有证据时将模型自动评分变成线上拦截器，或增加循环重写调用。
