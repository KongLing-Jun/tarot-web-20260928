## 1. 目标与完成定义

让解读准确回应用户当前问题，理解用户已经表达的困扰、目标和限制，提供与处境相符的分析，减少可套用到任何人的安慰、重复建议和报告式表达。

共情的验收依据是能否回应用户原话中的具体经历与影响；不能依靠强化情绪、推测隐藏动机或肯定他人心理来营造“被看见”的感觉。塔罗牌提供解释视角，不能代替现实证据。

本方案分两次交付：

1. **第一阶段：内容与上下文。** 保留现有三段输出协议，改进需求理解、表达方式、追问事实保留和每日解读；完成旧版与新版实际输出对照。
2. **第二阶段：表达结构。** 根据第一阶段评估调整可选行动、简短追问和牌义展开，同时保持历史记录、流式展示和质量检查兼容。

第一阶段完成不等于整个方案完成。没有真实输出评估，只能报告工程实现和确定性回归结果，不能宣称“共情质量已达标”。

## 3. 范围与实施原则

本次覆盖首轮手动解读、Agent 解读、直接追问、补牌追问、每日一牌及其历史上下文。沿用现有抽牌、保存、重试和完成状态机制。

- 第一阶段不增加独立模型分析调用，不替换供应商或调整模型预算。需求理解作为现有生成调用中的写作准备，不新增必须解析的分析 JSON，也不要求展示内部推理。
- 复用当前 Prompt 构建入口和历史类型。只有确实无法表达“用户输入保留、失败回答排除”时，才最小化扩展契约，并保持旧调用有效。
- 不使用关键词分支为某个问题生成固定共情答案。正反例仅作写作示范，固定案例仅用于测试和评估。
- 暂不建设用户画像数据库、跨会话记忆、在线语义打分拦截或多 Agent 生成链。独立分析调用、自动二次改写和模型替换都应由评估证据驱动。
- 本方案不包含提交、推送、部署或修改现有 PR；实际执行时按当时授权处理。

## 4. 内容生成设计

### 4.1 在当前调用中理解回应任务

生成前应核对以下内容，但不向用户输出这些字段或分析过程：

| 要素 | 内容来源与边界 |
| --- | --- |
| 当前问题 | 优先回应本轮明确提问，不用旧问题替代 |
| 已知事实 | 用户明确叙述的事件、阶段、尝试和结果；保留来源与时间顺序 |
| 明确感受 | 用户自述的情绪、困扰或自我评价；未表达时不强行归类 |
| 目标与限制 | 用户想得到什么、明确不想要什么，以及时间、资源等已知条件 |
| 待核对解释 | 可以用于分析的可能性，与已知事实分开表达 |
| 关键缺口 | 只在会改变回答方向时提出一个具体问题；仍先提供可支持的回应 |

内部写作策略可区分“希望被理解、希望看清处境、需要做选择、需要下一步做法”。这些策略允许并存，以用户本轮诉求确定重点，不给用户贴心理标签，也不扩大牌阵决策 JSON 的职责。

### 4.2 具体共情与处境分析

建议的组织顺序为：回应已知处境及其影响 → 回答当前问题 → 分析关键分歧或阻碍 → 给出有依据的下一步或关键问题。它是写作参考，不要求每次凑齐四段。

- 表达强度不超过用户证据。用户说“有点犹豫”，不写成“长期压抑、备受折磨”。用户没有表达情绪时，可以直接分析事情。
- 选择题比较收益、代价、限制与可逆性；关系问题区分实际互动、用户期待和未知的对方想法；行动问题识别当前障碍，避免把多项任务包装成一个小步骤。
- 不将所有问题归因为缺乏自信、需要成长、需要设立边界。每个原因都应能指出事实依据，或明确作为待核对解释。
- 用户只想表达困扰时，可以回应和澄清，不强迫其采取行动。用户明确拒绝某个方向后，不把它重新包装成隐藏需求。
- 第一阶段仍保留行动章节：确实不适合行动时，用与当前处境相关的简短支持或必要澄清承接，不能填充固定“你不必急着行动”。第二阶段再允许省略该章节。

### 4.3 提示词整理与示范

将共享提示词整理为职责、事实边界、需求理解、表达原则、少量示范、输出协议；各牌阵只保留自身分析方法。删减重复表述时逐项对照已有事实边界回归，不能用减少字数作为唯一目标。

示范至少覆盖：投入后无结果、自我怀疑、选项冲突、关系目标纠正、已尝试建议但无效、单纯倾诉。用同一事实的差回答与较好回答说明差异，明确示范不是本轮事实；每类示范不要求全部注入每次调用。

以下为虚构的措辞示范，不是实际模型结果，也不是完整塔罗解读：

> 用户：投了三个月简历，都没结果。我开始怀疑是不是自己太差了。
>
> 不理想：你需要保持积极，提升自信，继续优化简历，相信机会会到来。
>
> 改进方向：连续投了三个月却没有结果，你开始把这件事和自己的能力联系起来了。但目前的结果还不足以说明是你能力不够。接下来怎么调整，取决于问题卡在哪个阶段：你最近的申请，有进入过面试吗？

实际解读仍需结合当次真实牌面，在专业说明中解释联系，不能复用示范内容替代解读。

### 4.4 追问上下文

保留同一次占卜、目标回合之前已提交的用户问题与补充，即使当轮回答中断、取消或无效；排除未发送草稿、其他占卜内容和目标回合之后的信息。模型回答仅在满足当前有效完成条件时参与后续上下文，且明确属于此前回应，不是用户确认事实。

优先检查现有 `FollowUpHistoryEntry` 能否用“问题 + 空回答”表达失败回合，并明确空回答不应被重新过滤。若可行，不新增重复事实存储。补牌仅保留实际已抽记录，不根据回答文字重建；重试、刷新恢复和重新生成目标轮时不重复抽牌、不混入未来回合。

最新用户纠正覆盖对应旧说法；“AI 曾建议做某事”不能变成“用户已做某事”。对表面矛盾且无法确定是否更新的事实保留不确定性，避免静默选择。

### 4.5 第二阶段的结构兼容

先确定输出与消费规则，再接入生成：

| 场景 | 目标结构 | 牌义要求 |
| --- | --- | --- |
| 首轮完整解读 | 核心必需；行动按需 | 保留全部抽牌说明，可展开查看 |
| 简短事实纠正或直接追问 | 直接回应本轮；允许省略独立行动章节 | 按需要解释相关已有牌，不重复整份报告 |
| 补牌追问 | 回应本轮；行动按需 | 本轮补牌全部说明，可引用此前牌 |
| 每日一牌 | 简短自然段，建议按需 | 依据实际当日牌，避免泛化生活预测 |

优先在既有 Markdown 协议内扩展可选章节，不立即引入新的 JSON 输出格式。解析器须继续识别旧版章节顺序和无结构正文；界面不显示空标题；质量规则按解读场景检查必需项，不能把取消、截断或空正文误认成合法简答。确需新增模式字段时，采用可选字段与旧版默认行为。

## 6. 评估方案与建议门槛

### 样本与复现

建议首批采用 30 条经匿名化的真实问题，覆盖首轮、直接追问、补牌和每日场景，并覆盖六种牌阵。另补成对边界案例：想复合 / 明确不想复合、焦虑 / 明确说自己并不焦虑、建议未尝试 / 已尝试无效、失败回合补充后继续提问。人工案例标注为合成，不计入真实样本数量。

优先使用已经提供或授权使用的案例，不自动批量导出生产聊天记录。没有真实样本时，可先开展合成回归和代码工作，但真实效果验收保持“待完成”。真实原文和完整模型输出存放在指定的本地评估位置；仓库仅保留允许共享的匿名夹具、评分标准和汇总，不提交账号信息、密钥或个人身份信息。

每条保存：匿名样本 ID、场景、用户原文及纠正、已知事实、目标/明确拒绝目标、固定牌阵/牌位/正逆位、版本和提交号、模型标识、非敏感生成参数、评估日期、完整正文、终止状态、时延和可取得的用量。缺失字段记为未知，不推算不存在的数据。比较时固定模型和输入，先比较提示词；同一输入保持原牌，不重新随机抽牌。

### 评分规则

隐藏版本标识并随机安排 A/B 顺序，建议由两位评审独立判断，分歧保留原始评分并复核。只有一位评审时如实标注限制。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 需求回应 | 回答错目标或忽略纠正 | 部分相关但未解决主要疑问 | 直接承接当前目标与纠正 |
| 具体共情 | 无依据贴标签或套话 | 温和但泛泛而谈 | 与已知经历和影响对应，强度合适；无情绪需求时不强加 |
| 分析价值 | 只复述问题或套牌义 | 有解释但依据或关键分歧不清 | 区分事实和解释，指出影响判断的关键条件 |
| 建议适配 | 不可执行、忽略限制或强推行动 | 可做但笼统 | 与分析和限制一致；不需行动时适当回应 |
| 自然表达 | 大量可替换套话和重复标签 | 基本通顺但重复 | 连贯、具体、篇幅符合问题复杂度 |

严重事实错误单独记录，不用平均分抵消，包括：编造已发生经历、把对方想法或未来写成确定事实、忽略用户明确纠正或拒绝目标、写错实际抽牌。每个评分和错误必须附输出原句及对应输入依据。

**建议验收门槛，尚未达到或验证：**

- 真实样本中新版盲评偏好率至少 70%；以全部有效样本为分母，平局不算新版胜出。30 条有效样本对应至少 21 条偏好新版。生成失败计为新版未胜出并单列，不能为提高比率静默剔除。
- 验收集内严重事实错误为 0；各场景的需求回应和具体共情平均分不低于旧版。报告样本量，不能将小样本结果外推为线上保证。
- 同类自动化回归通过；首 token 时延、总耗时、用量和失败率提供旧新对照。未建立基线前不虚构性能改善或可接受增幅；增加模型调用时须重新评估成本。

测试失败、模型输出未取得、评分分歧与跳过项均保留。提示词字符串包含某项要求的测试，只证明要求进入请求，不证明模型遵守。

## 8. 风险与后续决策

| 风险 | 处理方式 |
| --- | --- |
| 共情写成猜测内心 | 对每个情绪/动机断言核对用户原话，使用明确反例评估 |
| 示例被复制成新模板 | 多场景与成对反事实测试，检查与本轮无关的示例细节泄漏 |
| 保留历史增加噪声与长度 | 先区分用户输入和模型回应；测量长度，确有需要再设计摘要，不能丢弃明确纠正 |
| 简短格式掩盖不完整生成 | 完成状态与内容结构分开判断；保留截断、取消和无有效正文回归 |
| 只看一次随机输出得出结论 | 记录完整版本与参数，对争议案例复跑并报告波动，不挑选最佳结果 |
| 用户实际痛点与代码推断不符 | 以真实不满意样本优先调整示范和评价，更新本方案假设 |

只有完成同输入对照后仍存在稳定缺陷，才评估独立需求分析、带反馈的重写或模型替换。比较候选方案时固定事实、牌面与评分规则，并同时记录时延和费用。重新生成反馈入口属于后续可选任务，当前不新增页面控件或自动二次调用。
