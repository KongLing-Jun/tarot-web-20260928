# 解读质量基础保障：小步实施方案

分支：`codex/integration-20260921`。依据：[准确度续评](../reviews/reading-accuracy-review-20260921.md#继续复核下一轮应先解决什么)。

## 本轮目标与边界

先解决能通过程序验证的评测统计、牌面来源及逐牌说明完整性，不把这些工程改动称为实际模型语义准确率提升。不切换默认 P0，不修改模型参数、不调用模型、不读取留出题正文。保留工作区已有的界面与本地配置改动。

## 分步实施

1. 评测分母：冻结实际计划尝试次数；生成失败、双侧缺失、未选入评审的配对保留在范围清单。旧胜率字段含义不变，增加可明确计算的全计划指标；旧材料缺失计划信息时标未知，不假装知道完整分母。
2. 牌面来源：复用记录解析中的标准牌库解析，普通入口按注册牌阵规范化牌位资料。验证原牌数量、合法牌位、方向类型和同轮重复。每轮补牌分别检查，保留历史补牌位置及跨轮相同牌；错误请求不产生模型调用或聊天记录。
3. 说明覆盖：区分协议完整、逐牌覆盖和语义质量。首轮开始逐牌说明后必须覆盖全部原牌；补牌轮必须覆盖本轮补牌；同一牌位不得重复解释。直接追问、每日无全牌覆盖要求。完全省略逐牌说明保持兼容倾诉/澄清，并记录 `omitted`，不计作全牌说明完整。
4. 综合验证：先跑每步红/绿回归，再跑完整测试、类型检查、lint 与构建；只对新失败或新改动补跑。进行独立代码复核，更新验证结果及剩余限制。

## 验收重点

- 同一 ID 的伪造牌名、关键词或牌位文字不能进入普通解读的上游输入或记录；标准客户端有效输入的 P0 提示词不变。
- 未知牌、未知阵、数量不符、同轮重复、空补牌应返回 400，且在记录/模型调用之前结束。
- 补牌的跨轮重复不误判为同轮重复，历史自定义位置仍可使用。
- 一条 core 加 end 可作为简答，但覆盖指标必须是 `omitted`；只解释部分必需牌位不能发出完成事件，保留已校验的有效正文。
- 缺失生成和裁判失败不能通过从分母消失而提高全计划指标；限制评审数量时仍披露未评审范围。
- 历史评测文件保持兼容，不回写原有实验产物。

## 后续语义实验

在本轮工程基础通过后，再冻结单变量候选、行动建议评分、校准集与调用预算。模型生成成功、引用真实和覆盖完整分别是不同指标，仍不能证明推论符合用户事实。真实模型对照与用户盲评不在本轮无网络验证中冒充完成。
