# 从提问到现实复盘：实施与验证记录

日期：2026-09-10。

## 已实施

- 首页主入口直达对话，手动选阵为次入口；缩小品牌标题，每日牌预览位于入口之后；窄屏按钮完整显示。
- 手动与自动提问共用可跳过的提示、感受及示例辅助。所有内容先进入草稿，保留原文字、去重、允许修改删除，明确发送后才提交。
- 两种解读均有纠偏快捷草稿；这些草稿发送时直接使用既有牌面与追问历史，失败重试也不触发补牌判断。
- 保留原有三段解析协议，界面展示“事情怎么看 / 可以怎么做 / 牌义依据”，牌义默认折叠。中文正文及输入使用统一正文字体。
- 历史列表、详情可恢复到对话页，保留原问题、牌面、追问及原记录 ID；“记录尝试 / 更新进展”继续写入这条记录。
- 恢复时原牌和历史补牌直接显示；加载、错误、已删除、首轮未完成均有相应处理。切换记录会隔离旧流回调和晚到请求；离开时保存已显示的追问片段；截断追问不会在恢复后成为完整上下文。
- 提示词默认收敛到一个小行动，要求理由、观察点及事实边界，承接最新纠正和现实进展。

沿用现有 API、Reading/FollowUp 存储契约，未增加独立情绪、行动或反馈实体。小程序迁移计划和任务清单保持原状；未发布上线。

## 真实模型质量评阅

使用项目现有模型配置和评估脚本；超时、输出预算从私有运行配置读取。输入均为 tests/fixtures 的合成场景，非用户真实会话。每场景生成两次，首轮 24 份发现问题后调整提示词，再生成最终 24 份。

评阅分为首轮、最终重点场景和最终其余场景三个批次。生成样本、提示词及响应统计附件已清理，保留以下检查结论和问题说明；样例编号用于标识历史批次。

**语义质量未全部通过。** 行动范围已有收敛，例如从筛选多个岗位缩到阅读一个岗位职责，从项目卡加口述及补证据缩到一个项目的三行说明。但最终样本仍有：

- correct-feeling-1：接受感受纠正后，仍把“面试邀请”压缩成“一次面试”，事件阶段可能漂移。
- attempt-failed-1：出现“继续盲投”和未确认的焦虑，暗示用户旧方法或感受。
- celtic-cross-2：将未提供的试做反馈当作尚不存在。
- timeline-1：结尾暗示用户一直停留在准备或构思，缺少对应事实。
- real-progress-2 和 extras-2：仍有一个问题并列多项询问，或一个行动包含多个步骤的倾向。

这些是实际评阅发现的模型局限，不能用格式测试通过来替代语义验收，也不能把每场景两次的结果当作生产成功率。本次没有用固定模板或前端替换来掩盖这些问题。

## 兼容性边界

Reading 没有可靠的首轮完成状态字段。存在 exchangeId 的记录通过现有聊天分页接口核对；无关联日志的非空旧正文保留并提示完成状态未知。空正文、仅思考、已识别但缺段的协议正文，以及关联日志显示中断的记录，都提供保留原牌重试。日志被清空、未保存完成元数据或模型截断但日志标记结束时，无法完整重建历史状态；本次未为此扩展接口或数据库。

离开页面时的追问快照使用现有 keepalive 保存队列，同一页面内再次读取会等待该记录的待完成写入；这不能保证断网或浏览器强制终止时仍能保存尚未到达服务器的数据。
