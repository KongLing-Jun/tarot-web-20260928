# 解读个性化优化：方案与实施记录

日期：2026-09-24。用户反馈：回答空泛、套话多，没有结合具体情况。

## 已确认的现状

- 普通解读通过服务端 `buildReadingMessages` 注入 system 规则与 user 材料；原问题、实际牌面和有效追问历史均有传输路径。
- 本机未显式配置解读 profile，默认 P0；意图识别开关未配置，默认关闭。此结论不代表远端配置。
- P0 注入完整长牌义，部分文本包含第二人称经历与通用劝告；同时要求不编造事实。判断/趋势题容易被写成通用行动建议。
- 核心、行动与各牌说明职责重叠，可能重复同一结论。
- 在线质量校验仅覆盖章节和牌面声明，不能判断是否结合用户背景。泛用但结构正确的回答可以无警告通过。
- 历史 P1、提高思考强度、二次编辑没有证明能稳定解决语义问题。不得把代码测试或模型正常返回称为内容质量通过。

## 本轮实施范围

1. 新增可回退的 `p2-context` 候选，保留 P0/P1 原有行为与冻结对照。复用已有标准牌面和用户原文证据构建器，使用普通 Markdown 输出，不引入 NDJSON 输出负担。
2. 把用户原文、最新问题、历史模型回答、牌面主题明确分开；覆盖首轮、直接追问、补牌、每日一牌、重新生成。即使意图服务关闭也能使用原文背景。
3. 按判断、选择、方法、倾诉分配回应任务；说明已知限制如何改变建议，已做的动作不重复布置。信息缺失影响方向时只澄清关键项；不编造背景来制造具体感。
4. 减少章节重复：核心给答案与必要理由，行动仅补充尚未给出的做法，各牌说明补充独特象征依据。
5. 新增独立的合成开发评测集，检查同牌不同目标/时间/已做事项、背景补齐、最新纠正与倾诉。复用冻结提示词、预算限制、失败留存和匿名对照工具，不读取既有留出题正文。
6. 执行程序验证与小规模真实模型对照，记录逐题事实和上下文使用情况。是否切换本机候选以结果为依据；远端部署和意图数据库迁移另行验收。

## 验收标准

### 程序层

- 新 profile 的所有正文入口均使用 system 规则与 JSON 材料；原文完整保留，模型旧答不混为用户事实，隐藏推理不进入历史。
- 牌面恢复标准关键词和解释范围，不注入长牌义中的现实断言；原始牌库展示不受影响。
- 重新生成保持同一问题和牌面，上一版回复标记为模型材料；P0 冻结哈希不变。
- 评测元数据不进入生成提示词；所有计划调用保留状态，准备阶段不发网络请求。
- 相关回归、全量测试、类型检查、lint、格式和构建通过；失败如实记录。

### 语义层

- 用户事实不是只被复述，而是实际影响判断、范围或下一步。
- 成对背景有实质差异时回答合理调整；相同结论仍可正确，但必须解释改变的权衡，不强求反转。
- 不重复布置已完成的任务，不忽略明确时间/资源限制或最新纠正，不把用户猜测当事实。
- 判断题回应所问，倾诉不强塞行动，背景不足不编造故事，各章节不重复同一个建议。
- 小规模开发对照只能提供初步证据；不替代独立留出、用户盲评或线上效果，不宣称预测准确率。

## 后续建议

- 收集经用户允许的真实失败案例，保留问题、牌面、背景、版本与输出，不把敏感对话提交到仓库。
- 复用现有场景入口补充事情、目标、限制与已尝试方法；对会改变答案的缺口做一次必要澄清，避免咨询问卷式阻断。
- 意图服务启用前验证对应数据库迁移、鉴权、持久化和浏览器完整链路；提取器不能创造用户未提供的背景。
- 不以关键词命中冒充语义个性化，不在在线链路新增一次未经证实有效的模型审稿，不同时变更模型和思考参数。

## 实施和验证结果

### 已实现

- 新增 `lib/api/reading-context-prompt.ts`，版本 `2026-09-24-p2-context-r3`；复用 `createReadingEvidence`，提供标准牌面主题、按时序用户原文、最新消息指针与独立的旧模型材料。输出继续使用现有 Markdown 章节，不增加在线模型调用。
- 首轮、直接追问、补牌、每日和重新生成接入 `p2-context`；由服务端配置选择，客户端不能覆盖。默认仍为 P0，P0 冻结提示词哈希保持不变。
- 追问重生成使用独立 `regenerationDraft`，保留 `previousReply` 首轮解读，避免“第二条建议”等指代在重生成时丢失。新增 direct/extras 回归先复现再修复。
- 通用提问入口的开头示例和占位提示引导补充目标、限制和已尝试方法；保留自由输入、仅填草稿、不自动提交的行为，场景专用开头仍沿用现有内容。
- 新增 `tests/fixtures/reading-context-cases.ts`：12 个独立合成开发输入、6 对相同牌面的背景变化。评测新增 `--suite context`，冻结 profile、消息、哈希和全部计划尝试；裁判用的 knownFacts/goal/review 不进入模型输入。
- P1 样本仅在选择 P1 套件时动态加载，context 路径不加载混合留出数据集。没有读取既有留出题正文。

### 真实模型对照

本轮共 **48 次真实生成**：P0 基线、P2 r1、r2、r3 各 12 次，每题每版一次。全部使用本机配置的 `deepseek-v4-flash`、thinking enabled / low，响应报告 `deepseek-flash`。没有自动重试、裁判调用、线上采样或真实用户资料上传。各轮共使用供应商报告的 **128,579 tokens**。

| 版本 | 完整生成 | 首个有效正文 P50 | 完成 P50 | 全文字符中位数 |
| --- | --- | --- | --- | --- |
| P0 | 12/12 | 4.885 秒 | 7.330 秒 | 577 |
| P2 r1 | 12/12 | 3.088 秒 | 6.265 秒 | 663.5 |
| P2 r2 | 12/12 | 4.362 秒 | 6.857 秒 | 659.5 |
| P2 r3 | 12/12 | 5.208 秒 | 6.491 秒 | 494.5 |

此处 P50 使用常规中位数（偶数样本取中间两项平均），字符数含 Markdown。P0/r1 同时运行、各自并发 1；r2/r3 先后运行、并发 1。调用时段不同，样本仅 12 题且没有重复采样，不用于宣布延迟、质量或预测准确率提升。

原始冻结材料与输出位于本机忽略目录 `docs/verification/context-20260924/`，分别为 `p0-*`、`p2-context-*`（r1）、`r2-*`、`r3-*`。`review-p0-r3/blind.md` 保存 12 对匿名材料，`blind-key.json` 中的 `scope` 与 `failures.json` 保留完整比较范围。只生成了盲评材料，未运行裁判，也未进行用户盲评。以下为知晓版本的代理逐题复核，不是盲评胜率。

### 发现与决定

r1 更积极地利用用户时间和目标，但多次把牌面主题扩成心理状态、增加任务和篇幅。r2 加入事实边界示例后仍未稳定消除问题。r3 在本轮 JSON 材料末尾增加明确输出约定，减少了一部分章节重复，仍有下表限制。三个版本的失败原文全部保留，没有只保留最好的回答。

| 成对检查 | r3 实际表现 | 判断与限制 |
| --- | --- | --- |
| 时间：20 分钟 / 三晚各一小时 | 短时题偏观点句与口述，长时题提到分晚推进 | 有变化；短时题要求先找未读过的人复述，再说“剩下二十分钟”，既引入未确认陪练资源，也没有扣除已用时间；长时题仍把未写稿扩写为在多个观点之间犹豫。 |
| 已做：未列提纲 / 已试讲超时 5 分钟 | 后者优先压缩到 10 分钟，不再从零备稿 | 使用了实际反馈；仍出现“压力更可能来自与讲完所有内容较劲”等无来源心理解释。 |
| 目标：减少沟通 / 认识附近的人 | 同样牌面下分别推荐 A / B，理由使用活动形态与目标 | 本轮符合目标变化要求；不代表其他目标题已验证。 |
| 背景：对象不明 / 已明确转班条件 | 补足条件后直接说“转班”，不再要求重复确认课程内容 | 具体题改善；缺对象题仍先写泛用内省解释，再询问事情和阶段，没有做到先澄清。 |
| 最新纠正：未回复 / 已确认时间地点 | 区分等待答复与已确认安排；已确认题不再诊断用户焦虑 | 改善；已确认题擅自把“提过以后聚聚”说成“口头提过”，来源未说明沟通方式；未回复题仍带有等待不安的暗示。 |
| 回应需要：一句话术 / 只倾诉 | 话术题提供可使用的句子；倾诉题没有行动清单 | 倾诉题仍多出逐牌标题，缺少对应二级章节，结构检查出现 warning。 |

**决定：本轮不将 P2 切换为默认，也不修改本机或远端私有模型配置。** 原因是已观察到的事实扩写和澄清行为未达标，不是因为接口失败。工程实现可以用于继续复现和对照，但“空泛且不贴合”的整体产品目标还不能宣称解决。单纯增加规则、JSON 分区和示例均不足以保证当前模型遵循要求。

在线检查继续只报告结构和牌面，不增设伪装成语义质量的关键词门槛。下一轮应固定 r3 与这些失败样本，先比较模型是否能遵循同一事实边界，或单独验证更简短的回答合同；不同时改模型、提示词和背景提取，也不将这 12 道已用于迭代的题当独立留出集。

### 复现与回退

准备与运行继续使用现有 CLI。以下 `新目录` 必须替换为不存在的输出目录；模型、端点和凭据从私有配置读取，不出现在命令中。为复现本轮思考策略显式使用 enabled/low，超时和输出上限沿用本机配置。

```powershell
npx tsx scripts/evaluate-reading-output.ts --prepare --suite context --profile p2-context --stream --thinking enabled --reasoning-effort low --attempts 1 --max-requests 12 --output 新目录/frozen
npx tsx scripts/evaluate-reading-output.ts --run --input 新目录/frozen --attempts 1 --max-requests 12 --concurrency 1 --output 新目录/results
```

离线对照无需修改服务端默认。只有在单独受控环境需要验证应用链路时才配置 `READING_PROMPT_PROFILE: "p2-context"`；当前候选未通过上线验收。回退值为 `"p0"`，配置按请求读取；源码或构建变更需按实际开发/生产启动方式重载。
