# 微信小程序前端风格一致性审查

审查日期：2026-09-18<br>
代码分支：`codex/integration-20260917`，提交 `d6b56d3`，已合入 `main@669fe90`。<br>
方法：通过浏览器视图工具操作页面，逐屏截图并检查保存后的图片；辅以 DOM 实际尺寸、计算样式及相关源码核对。本报告不修改产品代码。

## 1. 总体评价

**整体已经具备“深色、古金、塔罗、月夜”的共同主题，但组件规则尚未统一。** 首页与提问流程偏华丽插画，今日、牌典、我的偏星空书页，轨迹与聊天记录偏紫黑色工具页面。三组页面单独看都有方向，连续切换时，标题、背景、返回按钮和底栏会明显变化。

优先处理的不是把所有页面做得一样，而是统一同一种操作的外观、同一级标题的尺度、导航图标与基础配色。猫、月亮、指南针等不同插画可以保留。

发现 **1 项明确的操作入口缺陷**：今日页返回链接仍存在于 DOM，但高度为 **0px**，且没有可见箭头。另有多项风格差异，详见下文。

## 2. 审查范围与证据边界

- 统一视口：390×844 CSS px；单张截图为390×844，没有添加手机外框或微信系统栏。
- 使用当前源码的3001开发服务，通过4114隔离预览提供登录态；未使用上一轮3000构建作为本轮证据，避免遗漏最新样式。
- 用户昵称、余额、收藏数量为测试数据；轨迹、聊天、订单为无记录状态。收藏数量不用于评判真实数据一致性。
- AI与支付在隔离环境中主动关闭。图中“服务暂不可用”“暂无套餐”**不代表线上故障**。
- 本次查看的是小程序内嵌H5的手机布局，**没有连接微信开发者工具或微信真机**。原生导航栏、胶囊、安全区、iOS字体回退及真实支付界面仍需真机核验。
- 未覆盖真实聊天长记录、生成完成的解读报告、非空历史列表、支付结果和所有异常状态；不宣称全站无障碍合规。

## 5. 具体问题、依据与建议

### A01 · P1：今日页返回入口不可见

**证据：** 图04左上没有返回图标。DOM存在“返回首页”链接，实测为 **44×0px**。相对地，自选提问页的返回按钮为44×44px。

**原因已核对：** `app/daily/page.tsx:255` 使用没有子内容的Link，依赖 `data-small-icon="back"`；当前 `app/_styles/small-actions.css` 已只给显式surface操作提供皮肤，不再提供旧的图标呈现与尺寸规则。`daily.module.css:18` 的back仅有对齐和上边距。属于合并后的组件依赖不兼容，不能靠颜色调整解决。

**建议：** 返回组件自己提供真实图标和完整点击尺寸，共享样式只提供主题；至少补充返回链接非零尺寸、可见图标及导航结果的浏览器回归检查。

### A02 · P2：相同底部导航在不同页面变形

**证据：** 图01、04、05、09的“对话”使用月亮图标；图07、08变成对话气泡。轨迹页选中项有明显圆形暖金背景，其他主页面主要通过图标和文字变金区分。

**源码佐证：** `components/history/HistoryPageFrame.tsx:34` 单独传入 `chatIcon="message"`；`HistoryArchive.module.css` 对选中导航另加圆角背景。

**建议：** 同一导航目的地固定一个图标和一套选中态。页面插画可以改变，底部导航不应随页面换皮。聊天记录页若属于轨迹二级页面，建议标题明确叫“聊天记录”，并保持清楚的返回关系；不要仅为了名称相似就强行改为高亮对话。

### A03 · P2：返回操作的位置、形态和强调程度不一致

**证据：** 图02、11为左上44px细圆框；图06为右上金色填充圆框；图08为左上箭头加“轨迹”；图10为较弱的“← 返回我的”；图12为胶囊“返回”。图04则不可见。

**建议：** 对普通二级页面统一左上返回、同款箭头、同一点击区。全屏牌义虽然通过dialog实现，视觉仍更像独立页面，应明确选用“返回”或“关闭”的一种导航语义，而不是把返回箭头放在通常关闭的位置。

### A04 · P2：同级页面标题缺少统一尺度

下表为本轮浏览器计算样式，不是估计值：

| 主页面标题 | 字号 | 字重 | 计算颜色 |
|---|---:|---:|---|
| 今日一牌 | 24px | 400 | rgb(234,228,212) |
| 牌典 | 40px | 400 | rgb(234,228,212) |
| 轨迹／聊天归档 | 36px | 400 | rgb(255,232,171) |
| 我的 | 32px | 300 | rgb(238,229,211) |

**影响：** 牌典标题约为今日标题字号的1.67倍，主页面切换时层级感跳动。首页品牌大标题可例外；不能把今日的牌名44px与普通页标题直接当成同一层级。

**建议：** 普通主页面标题选定同一基准（可从32px试排），再为品牌首页、牌名和选阵舞台定义明确例外。英文副标题统一位置、斜体规则与大小写；目前今日/牌典是下方斜体，购买页是上方全大写，我的没有英文。

### A05 · P2：基础背景与金色亮度分成两套

**证据：** 图04、05、09是蓝黑星空与月云；图07、08下半部大面积紫黑平底，标题与指南针更亮。源码确认轨迹背景基色为`#151321`，并有独立history金色变量。

**建议：** 统一基础背景和文字/边框/强调金色的角色映射。轨迹可保留指南针与较淡纹理，但不要靠另起一组局部颜色定义主题。装饰金可以更亮，正文金保持稳定。

### A06 · P2：小按钮没有按用途形成稳定规则

**证据：** 图07、08工具按钮实测高32px、圆角8px；图06收藏是方角边框，图09购买是下划线文字链接，图12返回是胶囊。图03感受选项是方形复选卡。

**判断：** 复选卡、列表入口、标签页本来就不必长得一样。真正需要统一的是同一种操作的外观与尺寸。不能再次通过“所有button统一套皮肤”来解决。

**建议：** 建立返回图标、轻量工具按钮、文本链接、筛选页签、复选卡这五类规则。将可见外观大小与点击区域分开，建议移动端点击区至少44px作为项目目标。32px现状是触摸风险，不在本报告中直接判定违反某条无障碍标准。

### A07 · P2：品牌名称处于两种版本并存状态

**证据：** 本轮浏览器标题为“月映卡语”，`app/layout.tsx:40`与其一致；图01、05、06、09仍显示“觅映／MIYING”，首页英文为Miying。

**建议：** 先确定当前对外名称，再集中管理浏览器标题、微信标题、首页Logo文字、英文名、页脚及分享文案。此项需要产品决策，本报告不推测新旧品牌哪个正确。

### A08 · P2：购买页字体与阅读页衔接突兀

**证据：** 图10中文标题、说明、规则、记录正文整体显粗；图04、05、09较细。购买页又使用大写英文上标，与相邻“我的”页面排版不同。

**建议：** 标题用品牌衬线，支付说明与状态用稳定正文样式，减少所有文字都呈现强调态的情况。字号和字重用显式角色定义，避免不同系统中文回退字体决定结果。

### A09 · P3：插画与线条精细度不同

**证据：** 图01猫较柔和，图02/11边框明亮且装饰密集，图04植物很细很暗、札记羽毛却较粗，图07指南针高光更强。

**建议：** 保留不同主题插画，统一光源、金色饱和度和装饰密度上限。小图标单独使用同一套线条与视觉重量；不要把插画和操作图标混成一种尺寸标准。

### A10 · P3：关键词、分割线和英文装饰的语法不一致

**证据：** 今日关键词为两列下划线，牌义关键词是正位金色/逆位蓝色块，牌典列表是点分隔文字；首页是植物月相分割线，今日是星形细线，轨迹主要是空白。

**建议：** 这些差异可按任务保留，但应写清用途：列表用紧凑文本，详情用标签，强调阅读用两列排版。分割线选一套基础样式，再允许仪式页面使用装饰版本。不要把装饰性关键词做得比真实可点击按钮更像按钮。

### A11 · 待验证：选阵页首屏主要操作未完整显示

**证据：** 图12在390×844下，底部“使用此牌阵，开始洗牌”按钮只有上半部分出现在首屏。

**判断边界：** 这是首屏可见性观察，不证明按钮不能通过滚动访问。本轮未继续抽牌，也没有验证微信底部安全区。

**建议：** 真机检查矮屏及安全区，确保主要操作可完整滚动进入视口。若定位为单屏舞台，则需压缩卡牌展示高度或留出底部操作区。

## 6. 建议统一的规则

| 对象 | 建议 | 保留的合理差异 |
|---|---|---|
| 底栏 | 图标、文字、选中态和高度全局唯一 | 全屏流程可按产品逻辑隐藏 |
| 返回 | 同一箭头、左上位置、44px点击区 | 弹窗关闭用明确关闭图标 |
| 标题 | 主页面统一字号/行高/字重；英文规则统一 | 品牌首页与塔罗牌名允许更大 |
| 颜色 | 统一背景、正文、次正文、边框金、强调金 | 正逆位语义色、主题插画可不同 |
| 小操作 | 按语义分组件，不按所有button一刀切 | 复选卡、页签、文本链接各有规范 |
| 大按钮 | 本轮先记录差异，单独确定主CTA规范 | 不应因小按钮调整被连带覆盖 |
| 装饰 | 每屏一个主装饰中心，操作图标统一线条 | 猫、月云、指南针、书页可保留 |
| 品牌 | 名称与英文标识来自同一来源 | 页面功能标题不需机械加品牌名 |

## 7. 建议执行顺序和验收

1. **先修可用性：** 今日返回入口具有可见图标、非零点击区，点击能够回首页；真机核对选阵底部操作。
2. **再统一全局识别：** 品牌名、底栏图标和选中态、返回组件。连续切换六个主页面，导航不变形。
3. **统一标题与基础配色：** 在同一390px宽度下生成对照图，核对字号、顶部间距与背景基色；正文不被插画或低对比背景削弱。
4. **按语义整理小按钮：** 检查默认、按下、选中、禁用与焦点态；覆盖轨迹工具、收藏、返回、更多菜单，避免共享CSS覆盖组件布局。
5. **最后微调装饰：** 统一细线、金色高光和插画密度；不要为“统一”删除有效的信息层级。

后续应至少覆盖320px与390px手机宽度、iOS/Android微信真机；对深色次正文实测对比度，验证键盘焦点、读屏名称、长文本和非空列表。仅凭本轮截图无法给出这些检查已通过的结论。
