# 意图识别澄清策略与已有牌面修复

日期：2026-09-23。针对 [首次真实验收](./user-intent-live-20260923.md) 发现的两项问题修复，原始失败记录保留。

## 修改内容

1. 澄清只用于核心任务或对象不明确、无法在不编造信息的前提下回应的情况。岗位、行业、听众等只影响针对性的资料不再默认阻断流程；明确用户需要的具体产物确实依赖资料时仍可询问。二选一缺选项继续澄清。没有添加关键词白名单或按测试输入直接返回结果。
2. 查询用户所属记录后，复用 `parseDrawnCards` 校验真实牌面，以 `readingContext.hasExistingCards` 传给提取模型。回答策略复用同一状态，替换原先仅凭 `readingId` 推断有牌的逻辑。缺失或空牌面为 false，畸形牌面拒绝；客户端同名字段不参与判断。已有牌面细节由解读阶段提供，不让用户重复说明；换题仍不使用旧牌解释新话题。

涉及 [prompts.ts](../../lib/intent/prompts.ts)、[intent.ts](../../lib/server/intent.ts)、[intent-store.ts](../../lib/server/intent-store.ts)。未改 API 请求协议、数据库结构或前端交互。

## 真实模型复测

模型为当前配置的 `deepseek-v4-flash`。共 14 次真实调用：12 个识别样本、1 次自动选阵、1 次支持式解读。输入均为合成场景，复用实际提示词构建器和校验函数；无真实用户数据。

| 样本 | 修改前 | 修改后 |
| --- | --- | --- |
| 面试准备，保留未参加面试事实 | 追问岗位 | 直接准备方向，reading |
| 纠正为同事并解释原牌 | 追问原牌 | correct + explanation，复用原牌 |
| 换题准备汇报开场 | 追问主题、听众等 | switch-topic + reading |
| 不建议辞职，只建议面试准备 | 追问岗位 | 保留禁止范围，reading |
| 提示词注入夹带准备问题 | 拒绝注入但追问岗位 | 引用校验通过，reading |
| 未提供两个选项 | 正确澄清 | 继续必要澄清 |
| 澄清后比较与只倾诉 | 符合预期 | 继续符合预期 |
| 新增读书会开场准备 | 未测 | prepare + reading |
| 新增只说明一个比较选项 | 未测 | compare + clarify |
| 新增解释服务端已有原牌 | 未测 | explain-cards + explanation |
| 新增确实未提供原牌 | 未测 | explain-cards + clarify |

原 8 个样本的完整流程断言从 3/8 变为 8/8，新增 4 个边界样本均通过，共 12/12。自动选阵正确选择二选一；支持式解读经人工专项核验，没有附加行动清单或要求补牌。

12 次识别平均耗时 5.311 秒，范围 2.776 至 7.897 秒。14 次调用供应商返回总量 27198 tokens。仅报告本轮观测，不用不同数量的小样本推导性能改善或生产准确率。

逐例结果、输入、回答与 usage 见 [复测记录](./user-intent-live-fix-20260923.json)，复现脚本为 [evaluate-user-intent.ts](../../scripts/evaluate-user-intent.ts)。每个样本本轮只运行一次，不声称穷尽所有语义或注入场景。
