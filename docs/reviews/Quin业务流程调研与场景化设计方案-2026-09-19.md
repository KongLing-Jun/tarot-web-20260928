# Quin 业务流程调研与场景化设计方案

调研日期：2026-09-19。目标：参考 Quin 如何帮助用户进入问题、选择解读方式、继续追问与回访，改善月映卡语的场景设计。本次交付为方案，不修改产品代码或模型配置。

## 1. 核心判断与证据范围

最值得借鉴的是：**用用户当前要解决的事情组织入口，通过少量背景让问题具体化，把推荐牌阵、解读和后续追问连成一条流程。** 不建议首先增加牌阵数量、复杂仪式或年度预测。

需要区分三件事：

- **公开可确认的功能**：来自 Quin 官网、FAQ 和官方商店版本记录。
- **流程推断**：依据这些功能重建的业务链路，不代表已经逐屏操作原生 App。
- **月映卡语设计建议**：下文场景名称、字段、确认流程与验收方法是针对本项目提出的方案，不能当作 Quin 已有界面。

已浏览官网产品展示，并检索官方说明；未登录原生 App、购买订阅、测试实体牌识别或测量实际解读延迟。没有证据判断其具体模型、提示词、RAG、Skills 或在线质量审查架构，也没有证据证明其回答质量优于本项目。

大陆版 App Store ID 为 `6480106163`，国际版为 `6502235206`，版本号及发布时间不同。不能把两个地区的功能记录直接拼成同一版本的完整体验。官网营销中的准确性或疗愈表述不作为效果验证。

## 2. Quin 的业务流程

### 2.1 功能证据

| 入口或环节 | 官方公开资料支持的内容 | 可以借鉴什么 |
| --- | --- | --- |
| 针对一个问题提问 | 说明问题、按问题推荐牌阵、线上抽牌、连续对话 | 从问题开始，让选阵服务于任务，而不是让新人先学习所有牌阵 |
| 日常指引 | 官网展示每日入口；大陆版更新记录包含明日运势 | 为低负担体验与持续使用提供独立入口 |
| 阶段性主题 | 大陆版有四季阵及秋分主题，国际版记录有年度解读 | 有明确时间范围的回顾主题；不能据此证明预测有效 |
| 现实牌组接入 | 官网介绍实体牌照片；FAQ 还描述手动选择实体抽到的牌及方向 | 同一解读能力接收不同抽牌来源，但拍照不是本项目首期需求 |
| 解读后继续 | 大陆版记录包含推荐追问、补抽建议牌、点击牌面查看牌义 | 让用户继续解决同一件事，并可查看解读依据 |
| 回看与个性化 | 官网展示提问日历、卡背与多种牌组风格 | 历史回看和风格选择属于体验层，不等同于提高结论质量 |

### 2.2 根据公开资料重建的链路

**问题型链路：** 提出困惑 → 匹配牌阵 → 抽牌或录入实体牌 → 解读 → 推荐追问／按需补牌 → 回看。

**日常型链路：** 今日或明日入口 → 轻量解读 → 日常回看；小组件也是公开的快捷入口之一。小程序端是否有可对应的入口能力需要另行核实，不能照搬 iOS 小组件实现。

**阶段型链路：** 季节或年度主题 → 相应主题解读 → 后续回看。官方公开资料没有充分展示如何把上次行动、实际结果和下次解读连成复盘，因此不能将“完整复盘闭环”归为已证实功能。

商业上，FAQ 同时描述免费单牌体验、按次牌阵购买和订阅。大陆版更新记录另有礼品卡及赠送占卜券。可推断其尝试连接“轻量体验—深入使用—付费／分享”，但没有转化率、留存或收入数据；本轮也未确认具体付费墙位置与地区价格，不建议照搬收费规则。[官方 FAQ](https://askquin.ai/cn/faq)、[大陆版 App Store](https://apps.apple.com/cn/app/quin-ai%E5%A1%94%E7%BD%97%E6%B5%8B%E6%B5%8B%E8%BF%90%E5%8A%BF%E6%84%9F%E6%83%85%E4%BA%8B%E4%B8%9A/id6480106163)

### 2.3 应当借鉴与暂缓借鉴

| 现在值得做 | 暂缓 | 原因 |
| --- | --- | --- |
| 具体任务入口、背景补充、贴题追问 | 大量卡背与抽牌特效 | 当前用户反馈集中在回答不清楚，装饰无法直接解决 |
| 按需推荐牌阵、查看实际牌义 | 自动生成任意牌阵 | 已有六阵足够验证场景价值；动态牌位会增加解释与验收难度 |
| 同主题继续、手动记录实际进展 | 季度／年度预测、复杂提醒系统 | 先验证一次任务是否解决，再验证复访需求 |
| 明确依据与未知信息 | Yes/No 式绝对裁决或读心包装 | 快速结论不能以虚构确定性为代价 |

## 4. 建议的场景库

场景按“用户要完成的任务”命名，爱情、工作、学业等只作为可选背景标签。一个场景可以用于不同生活领域，不能出现“写到感情就一律选关系阵”。

### 4.1 首期四个场景

| 场景卡 | 最少要弄清什么 | 用户期待的答案 | 牌阵选择与边界 |
| --- | --- | --- | --- |
| **两个选择，怎么选** | A/B 各是什么；最看重什么；有什么现实限制 | 各自取舍；在什么条件下更适合哪个选项 | 条件明确用二择一；只有一个选项时先补问，不能替用户发明另一个 |
| **这段关系，下一步怎么沟通** | 双方关系；最近一次具体互动；希望解决的问题 | 下一步适合怎么沟通、先核实什么 | 有互动背景可用关系阵；仅有猜测时先聚焦一个问题，不能确认对方心理 |
| **这件事卡住了，怎么办** | 已发生经过；当前卡点；尝试过什么及反馈 | 当前优先处理什么，以及判断是否有效的方法 | 梳理阶段用三张；复盘多段经过用时间之流；没经过就不补写“过去” |
| **整理当下，找到下一步** | 愿意分享的感受或事情；希望得到何种帮助 | 一个聚焦角度和可选择的小行动 | 默认考虑单张；用户只想整理文字时，不强制抽牌或假装已完成解读 |

“最少要弄清”不是把每列做成必填长问卷。已经写在自由文本中的内容不要重复询问；每次只展示当前缺失且影响选阵的一项，允许“不知道／暂不填写”。无法支持复杂牌阵时解释原因，提供更简单的观察范围。

已有明确场景和字段时，可以用共享指南中的规则推荐最小够用牌阵；无法可靠识别的自由输入仍走现有模型推荐。首期不增加一次模型调用来判定每一个表单字段是否齐全。

### 4.2 保留及后续场景

| 场景 | 定位与安排 |
| --- | --- |
| 每日一牌 | 保留独立轻量入口，不要求填写完整背景；有具体事件时可转入同主题对话 |
| 一个行动之后，想复盘 | 第二阶段。用户记录做了什么、实际得到什么反馈，再决定直接追问或补牌 |
| 多个因素，需要全面梳理 | 第二阶段进阶入口。背景充分且因素确实相互影响时才推荐凯尔特十字 |
| 季节／阶段回顾 | 第三阶段再验证需求，优先回顾目标、实际进展与下一阶段安排，避免包装确定预测 |

## 5. 页面与交互方案

### 第一步：按当前任务进入

首页保留“今日”和现有导航，在开始提问区域展示四个场景卡及“直接写问题”。卡片用具体任务名称和一句示例，不要求用户先理解牌阵术语。沿用现有暗色与金色主题及小按钮规范。

### 第二步：补充少量背景

复用提问页，展示该场景的两至三个短问题，按已有输入折叠已回答内容。示例仅作为 placeholder，不自动写入真实事实。用户可直接编辑原文、跳过可选项、切换场景且保留草稿。

### 第三步：确认问题与推荐牌阵

同一张确认卡显示：

- **这次想解决：** 用户问题或可编辑的提问草稿。
- **你提供的背景：** 用户输入原文片段，可展开查看。
- **建议使用：** 牌阵、张数、适合本题的理由，以及当前不能回答的部分。
- 操作：“按这个问题开始”“修改问题”“更换牌阵”。

确认前不抽牌、不启动解读；如未来接入计次收费，确认前不产生解读扣次。对尚未确定的字段，显示“未提供”，不能由模型自行填齐。为避免额外摩擦，确认问题与牌阵放在一个步骤，不做连续多页向导。

### 第四步：先回答问题，再展开依据

结果首先回答用户要做的决定或行动。无法确认的问题也要直接说清具体缺口，并给下一步可核实的事实，避免泛泛“看情况”。随后按需展开：用户原文依据、真实牌位及牌意、解释与行动选择。

例如用户实际输入“他两次取消见面，昨天主动提了周末改约”，问题是“我该不该主动确认时间”：可以提出确认具体时间的行动建议；不能扩写为“他一直很在意你，只是工作太忙”。前者是可执行选择，后者添加了未提供的心理与原因。

这部分是输出目标，仍需独立评测，不能因界面增加了“依据”标签就视为推论已正确。

### 第五步：继续这件事

结果后优先给“补充新事实”“把建议说具体一点”“记录尝试后的反馈”三个入口。具体追问可以由场景配置产生起步草稿，点击后允许编辑，不自动发送；后续有质量证据时再引入模型生成推荐。

追问保留原 `readingId` 和实际牌面。只有用户明确切换问题才开始新解读；补抽牌必须说明用途并让用户选择。历史页先保留现有按记录回看，再考虑场景筛选，不急于重做整个轨迹系统。

## 6. 与输出质量优化如何衔接

### 输入来源必须可追溯

场景标签、系统示例、推荐理由都不能进入“用户事实”。保留每段用户输入的原文和来源；确认后的问题改写也不能倒过来替代其原始证据。用户修改事实时，记录新版本及先后关系，解读优先采用最新明确纠正。

建议保存场景 ID／版本、用户原问题、用户字段原文、用户目标、确认状态和实际选中牌阵。当前 `Reading` 类型及 `lib/server/readings.ts` 的解析器会重建记录并丢弃未知字段；实施时必须同步处理类型、请求校验、持久化、恢复和旧记录兼容，不能只给前端对象添字段。

### 牌义只能解释实际牌位

继续复用现有牌位 ID、抽到的牌及正逆位。一个“关系沟通”场景不能把原本的某张牌偷偷重新命名为“对方真实想法”；更换场景也不能改写已经生成的历史牌位。

### 越界审查仍要独立做

逐字引用正确，只能证明引用存在，不能证明结论成立。仍需检查是否新增合同进展、具体日期、他人心理、过去事件及因果。规则和来源校验负责可确定的格式问题；离线语义审查与人工复核负责推论边界。

当前默认仍为 P0。`p1-grounded` 是候选，上轮 12 题中 11 题完整通过协议，仍发现越界，尚未完成新一轮对 P0 盲评并达到原定 65% 门槛。不得以“参考了 Quin”或“加入场景表单”为理由直接切换候选。[已有实施验收](./牌阵场景与可追溯解读实施验收-2026-09-19.md)

## 7. 分阶段实施与验收

| 阶段 | 交付 | 验收方法 |
| --- | --- | --- |
| **第一阶段：场景输入与选阵** | 四个场景、少量背景、合并确认卡、推荐与执行分离、自由提问兼容 | 四场景覆盖完整背景、缺信息、修改草稿、换阵、退出恢复；确认前不得抽牌或触发解读 |
| **第二阶段：同主题继续** | 场景快照、追问草稿、进展补充、历史恢复 | 更新事实后不丢原牌；最新纠正生效；旧记录可打开；不会重复保存为多次新解读 |
| **第三阶段：质量与复访实验** | 对照评测、用户任务测试；结果合格后再扩阶段回顾 | 分开衡量回答是否清楚、事实越界、等待时间和复访需求，不能只看点击量 |

### 对照实验设计

1. **先隔离场景输入的价值。** 固定模型、P0 提示词和同一组牌，对比自由提问与场景补充后的输入。新增事实必须来自真实用户补充；实验夹具可用已标注的合成输入，不能伪装线上用户数据。
2. **再隔离候选协议的价值。** 用相同的场景输入和同一组牌比较 P0 与 grounded 候选，沿用既有质量门槛及失败计入分母规则。不要同时更换模型、牌阵和提示词后把收益归因于场景。
3. **新增场景回归集。** 建议四场景各六题，共 24 题，覆盖信息完整、缺信息、事实纠正、关系读心、时间承诺和建议被误判等情况。此数量是拟议测试规模，不是已有实测结果；不要拿开发集调完后宣称通过封存验收。
4. **人工任务验收。** 除了 A/B 喜好，还问“它是否回答了你的问题”“你知道下一步可以做什么吗”“是否写入你没有提供的事实”。记录具体句子和原因，保留不喜欢与无效样本。

### 速度与质量分别计量

- 记录开始填写到确认的时间、确认到首个可见正文时间、确认到首个有效回答时间、完成时间；失败与中断单独报告，不能用失败早停制造速度改善。
- MVP 表单、确认和追问草稿不新增串行模型调用；能按明确输入规则推荐的场景可省去模型选阵，但要验证适配率，不能用错误选阵换速度。
- 不使用虚假百分比进度。保留实际流式状态、取消与重试能力；用户开始新任务时不得把旧任务迟到结果覆盖到新页面。
- 发布前应满足：输入来源与牌位关联测试全部通过，代表性评测中无已知严重事实越界；质量和延迟分别与本次真实基线对照。小样本未发现问题不等于线上零错误。

## 8. 推荐决策

先实施第一阶段，以“两个选择怎么选”完成一条最小端到端流程，再复用同一结构接入其余三个场景。这个场景的输入、选阵条件和输出取舍最容易验收。

保留自由提问、手动选阵、每日一牌和现有视觉体系。将“更容易说清问题”和“解读推论更可靠”作为两项独立交付：前者通过场景交互验证，后者必须继续通过来源核验、语义审查与真实盲评验证。

尚待原生体验核实的竞品细节包括：首次进入与登录门槛、付费出现时机、追问能否始终留在同一主题、失败后额度处理、不同地区功能差异。这些不影响先完成上述场景 MVP，但不宜据公开页面推断 Quin 的内部实现。
