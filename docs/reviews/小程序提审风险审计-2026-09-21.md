# 小程序提审风险审计

审计日期：2026-09-21。对象：当前工作区、配置中的线上 H5、微信官方当前文档。

## 结论与边界

当前项目存在支付接入、收费功能完整性、占卜表达、隐私与内容安全方面的具体问题；AI 类目资质和小程序主体权限还需要后台核验。仅重复上传小程序代码包，不能解决 H5 和服务端的问题。

尚未取得审核驳回原文、提审版本、微信后台服务类目、主体及资质材料，因此本报告是代码与规则风险审计，不代表已确认历次驳回原因。当前代码也不能直接等同于已提交版本或线上全部功能。

## 1. 高优先级：虚拟商品仍走普通小程序支付

- `app/profile/page.tsx:69` 提供“购买抽卡次数”。
- `components/CreditRecharge.tsx:90` 起展示次数套餐、价格和微信支付按钮。
- `miniprogram/pages/recharge/recharge.js:52` 调用 `wx.requestPayment`，服务端使用汇付普通小程序下单链路。
- 未检出 `wx.requestVirtualPayment`、米大师虚拟支付及相关支付签名接入。

抽卡次数属于项目内的数字权益，应优先核对虚拟商品支付要求。当前微信《平台运营规范》14.7 要求虚拟商品购买和支付接入小程序虚拟支付；普通支付成功不代表满足该要求。

**整改方向：**在后台核实商品和类目适用条件，按官方虚拟支付能力接入下单、确认交付、查单和退款。不能只隐藏 iOS 按钮；当前官方能力已经覆盖 Android、iOS、鸿蒙和 Windows。官方文档列明 iOS 还需要满足系统、微信版本、简称配置等条件，Apple 支付最低金额为 1 元，现有 0.01 元套餐也不能直接沿用到该渠道。

未使用真实账号确认线上支付开关或发起真实交易；若线上未开放购买，实际暴露程度应以微信内页面为准。

来源：[微信平台运营规范](https://developers.weixin.qq.com/miniprogram/product/)、[虚拟支付接入](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)。两页本次通过 HTTPS 成功读取。

## 2. 高优先级：产品仍包含明确的占卜、未来结果表达

- `lib/tarot/spreads.ts:8`：“快速占卜”。
- `lib/tarot/spreads.ts:22`：“过去-现在-未来”。
- `lib/tarot/spreads.ts:97`：“对方的感受”。
- `lib/tarot/spreads.ts:186`：“即将发生的事情”。
- `app/profile/page.tsx:27`：“占卜次数”。

线上 `/spreads` 的公开 HTML 本次也包含“快速占卜”“近期未来”“最终结果”，不是只有代码注释存在这些文字。首页改为“观察角度”并没有改变整个产品的实际表达。

微信运营规范 6.1.3 禁止宣扬封建迷信。并非出现塔罗图片即可直接判定违规，但当前以抽牌解释未来、他人心理和关系走向的功能，具有较高审核风险。

**整改方向：**若定位为自我反思或卡牌文化，应把牌位定义、功能行为、模型输出和页面文案统一到这一定位，消除预测承诺。不能只替换名称、加“仅供娱乐”，也不能提审时隐藏功能、上线后恢复。

已有的 `lib/api/prompts.ts:23` 等规则强调不编造事实、不证明未来，这是正向措施，但与牌位的产品承诺仍不一致。

来源：[微信平台运营规范](https://developers.weixin.qq.com/miniprogram/product/)，6.1.3、5.19。

## 3. 高优先级：真实收费与实际权益未形成完整流程

`docs/PAYMENTS.md:5` 明确说明次数仅记录余额，尚未接入占卜或聊天抵扣，购买会真实扣款。检索当前解读、聊天、每日牌服务及余额触发器，也未发现相应扣次实现。

此外：

- `database/015_card_draw_offers.sql` 使用“月订阅”“年订阅”套餐名。
- `docs/PAYMENTS.md:17` 又说明所有次数长期有效，不自动续费，名称并不对应订阅周期。
- `docs/PAYMENTS.md:31` 说明退款仅由运营登记历史，页面没有退款申请入口，退款也不扣回余额。

这些是已确认的产品完整性问题，可能导致审核对收费目的、承诺权益及售后产生疑问，不等于已经证明存在诈骗或已收到此类拒绝。

**整改方向：**先定义并实现付费权益、消费时点、失败补偿、重复请求幂等、订单交付和售后。次数包按次数命名；退款应有用户可用的申请与处理路径。业务未完成前应持续停止对所有用户开放新购买，保留已有订单查询和售后，而非只在提审期间关闭。

微信当前运营规范 14.6 对退款申请渠道和退款路径有要求，应按实际业务落实。

## 4. 后台必须核验：AI 类目和资质

首页明确提供 AI 牌阵推荐、文本解读及追问，`app/api/interpret/route.ts` 实际调用模型，不只是静态图鉴。

腾讯 CloudBase 的官方上架说明要求申请相应深度合成类目；使用第三方技术时，需要技术提供方算法备案及合作协议等材料。该说明可作为材料清单参考，但不能把云开发的材料直接用于本项目实际的其他模型供应商。

**核验事项：**后台是否包含实际功能对应的“深度合成／AI 问答”等类目，主体是否可申请，协议与模型供应商及小程序主体是否对应。当前源码无法证明后台未办理资质。模型名称、备案信息公示也未在本次检查的页面代码中找到，应核对实际适用要求后补齐。

来源：[CloudBase 微信云开发在用证明](https://docs.cloudbase.net/ai/release/algorithm-filing)、[网信办生成式人工智能服务备案公告](https://www.cac.gov.cn/2024-04/02/c_1713729983803145.htm)。

## 5. 高优先级：用户数据处理缺少可见说明与权利入口

当前代码会创建微信身份账号、保存提问与回复，支持昵称和头像上传，并将问题发送给模型服务商。证据包括 `lib/server/auth.ts:61`、`lib/server/chat.ts:55`、`lib/server/profile.ts:15` 和 `app/api/interpret/route.ts:299`。

本次在页面、小程序和 API 源码中未找到完整的隐私政策、用户协议、同意记录、账号注销或数据删除申请路径。公开站点 `/privacy`、`/terms` 返回 404，首页也没有这些入口；这两个路径不是平台指定路径，404 只是辅助证据。微信后台可能单独配置了隐私指引，本次无权据源码断言后台未配置。

**整改方向：**核实后台隐私指引，补充 H5 中可访问的数据处理说明；明确运营主体、数据类型、用途、保存期限、模型及存储服务商、联系和删除渠道，在实际收集场景落实告知同意。不能简单把 `wx.login` 当作微信要求隐私授权弹窗的接口，也不能认为没有敏感原生 API 就没有 H5 数据处理义务。

来源：[微信平台运营规范](https://developers.weixin.qq.com/miniprogram/product/)，15.1、15.2；[腾讯云隐私保护指引说明](https://cloud.tencent.com/document/product/1301/97930)。

## 6. 内容安全：输入与模型输出没有独立审核层

`app/api/interpret/route.ts:76` 的校验主要是结构校验；`agent.prompt` 可直接透传，普通生成流程也未发现输入安全审核和输出安全过滤。`lib/auth/profile.ts:2` 对昵称主要检查长度和控制字符，头像处理主要检查图片格式。未检出微信内容安全 API 或其他独立审核服务。

这不代表上游模型完全没有安全措施，也不代表已复现违规内容；目前的工程事实是应用自身未形成可核验的内容安全机制。现有写作提示词和“牌义一致性”检测不能等同于内容审核。

**整改方向：**按实际场景接入输入、上传内容和模型输出审核，尤其处理流式响应先输出后审核的问题；补充投诉入口和处置流程。不能仅用关键词替换代替审核。

来源：[微信平台运营规范](https://developers.weixin.qq.com/miniprogram/product/)，5.18。

## 7. 技术待核验：开发环境关闭域名校验

`project.config.json:5` 和本机 `project.private.config.json:5` 均为 `urlCheck: false`；开发环境为局域网 HTTP，体验版与正式版为线上 HTTPS。文档中“默认启用”的描述与当前配置不一致。

这不是审核必拒的代码开关，但会掩盖 request 合法域名、web-view 业务域名、证书及主体权限问题。小程序首页先登录，登录失败后整个 H5 不会展示，故首页 HTTP 200 不代表审核员能正常进入。

**验收方式：**在开启域名校验、真机关闭调试模式的条件下，用新账号检查登录、网页进入、生成结果、历史保存和支付。后台核对业务域名与 request 域名，以及主体的 web-view 权限。官方文档当前明确个人类型小程序不支持 web-view；若本项目属于个人主体，此项会成为根本性问题。

来源：[微信 web-view 文档](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html)。
