# 解读质量离线回归

运行确定性回归：

```powershell
npx vitest run tests/agentDecision.test.ts tests/interpretationQuality.test.ts tests/interpretationCorpus.test.ts
```

固定语料位于 `tests/fixtures/interpretation-quality-corpus.ts`。每条包含问题、已知事实、固定牌阵及正逆位、人工编写的参考正文、不能接受的断言和复核要求。六种牌阵全部覆盖，不调用外部模型，不消耗 API 额度。测试对参考正文进行结构检查，再故意交换牌面方向验证错误能被发现。

线上确定性检查仅识别正文存在性、约定章节和专业说明标题中的明确牌面冲突。首轮和补牌可省略行动章节，仍需核心与对应牌义；直接追问可仅有核心或自然正文，不要求重新覆盖所有原牌；每日一牌不强制章节。补牌回合要求能识别本轮补牌，也允许相关原牌与历史补牌。未知或异常章节只警告；确定的牌位、牌名、正逆位冲突提示用原牌重新生成，保留现有文字。合法简答不会覆盖取消、中断、截断等生成状态。

这些规则不能验证事实真实性、心理推断、未来不确定性、行动质量或正文内部矛盾。专门的回归用例确认：一句错误的读心断言即使通过格式检查，也不能因此被宣称语义合格。质量结果中的“无问题”仅表示规则未检出问题。

修改模型或提示词时，使用固定问题和固定牌面生成候选正文，并保留完整输出、模型标识、提示词版本及评估日期。逐条对照已知事实与 `review`，人工记录下面各项“通过 / 不通过 / 信息不足”及对应的原句证据：

| 维度 | 复核内容 |
| --- | --- |
| 回应问题 | 核心结论是否回答当前问题，追问是否承接最新补充 |
| 事实边界 | 是否新增用户未提供的过去、情绪、资源或行为 |
| 牌面一致 | 牌、牌位、正逆位是否一致，当前模式所需牌位是否覆盖 |
| 不确定性 | 是否把对方心理或未来当作已知事实，条件是否写清 |
| 可行动性 | 建议是否具体、可执行、接续分析，是否观察真实反馈 |
| 内部一致 | 核心、行动、牌义说明是否相互矛盾 |

补充四类多轮检查：用户纠正已发生事实后继续追问；加入补牌后保留此前牌面与背景；重新生成时问题和所有牌面不变；每日解读不强行套用问答章节。传输中断、取消和保存失败属于结果状态回归，应与语义评估分开记录。自动测试通过不代表实际供应商模型已完成这一人工复核。

## 共情与需求分析评估

执行计划和评分标准见 [共情优化方案](tasks/interpretation-empathy/plan.md)，逐条记录用 [评分模板](tasks/interpretation-empathy/review-template.md)。新增合成输入位于 `tests/fixtures/interpretation-empathy-cases.ts`，覆盖六牌阵、目标正反对照、事实与情绪纠正、失败回合补充、倾诉和每日一牌。它们不是用户真实聊天，不能计入真实样本偏好率。

复用现有评估脚本冻结输入，再按冻结版本调用。以下 `<...>` 为执行时指定的新目录，不能原样运行：

```powershell
npx tsx scripts/evaluate-reading-output.ts --prepare --suite empathy --output <冻结目录>
npx tsx scripts/evaluate-reading-output.ts --run --input <冻结目录> --output <结果目录> --attempts 1
```

`--prepare` 不发模型请求；超时与输出预算默认取现有服务端配置，也可在准备时用 `--timeout-ms`、`--max-output-tokens` 明确指定。`--input` 校验冻结 Prompt 哈希、模型和预算，避免比较期间悄悄改变输入。每例保留完整正文、生成状态、确定性质量、耗时和可取得的用量；非流式评估的首 token 时延记为未知。输出目录已有记录时拒绝覆盖。

旧 Prompt 的结果也使用执行评估时的质量校验器，不能据此反推旧版前端告警。运行成功只表示得到完整有效正文；内容是否共情、是否推断过度，仍需对照输入逐条评审。失败回答不参与后续推断，但该轮用户已提交补充与实际抽牌应继续进入上下文，需同时检查刷新与重试边界。
