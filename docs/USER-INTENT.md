# 用户意图识别：实现与启用

执行计划：[plan](../tasks/user-intent/plan.md)，任务清单：[todo](../tasks/user-intent/todo.md)。

## 启用顺序

1. 在目标环境确认数据库后，使用现有迁移流程应用 `database/019_user_intents.sql`。该迁移仅新建用户意图快照表和索引，可重复执行。
2. 在服务端私有 `model.config.json` 设置 `INTENT_RECOGNITION_ENABLED: true`。缺省关闭，旧环境不需要新表即可继续原有占卜。
3. 刷新页面，使 `/api/config` 返回的 `intentEnabled` 生效。模型地址、凭据、调用预算继续使用已有服务端配置。
4. 先用测试环境确认澄清、修改、失败重试和跨用户隔离，再开启正式环境。回滚可以关闭开关；保留新表避免丢失快照。

尚未对当前非本机数据库执行迁移。2026-09-23 首次真实验收发现过度澄清及已有牌面状态缺失，现已修复；后续 14 次真实调用中，12 个识别样本及下游选阵均满足预设断言，支持式解读通过人工专项核验。详见 [修复与复测](./reviews/user-intent-live-fix-20260923.md)。这不替代数据库及完整链路验收。部署与启用必须使用目标环境自己的配置，不复制测试凭据。

## 运行流程

提问 → `POST /api/intent` → 服务端读取所属记录的用户问题 → 模型提取 JSON → 引用与协议校验 → 生成受控回答计划 → 保存不可变快照 → 返回澄清或允许继续。

场景和普通手动提问、Agent 首问及追问共用此接口。需要澄清时保留原输入，用户补充后再提交，客户端携带上一版快照引用，服务端保留原问题和补充消息。修改问题、换场景、取消或离开会使旧识别响应失效。识别未完成不会自动继续抽牌或发送解读。澄清仅针对核心任务或对象缺失；已经知道讨论的事情与期待回应时，可选的岗位、行业或听众等细节不阻断有限范围的回答。比较选项不全等必要信息仍须澄清。

服务端先验证记录归属，再校验实际 `drawnCards`，将 `readingContext.hasExistingCards` 传给提取模型；客户端不能自行声明该状态。记录 ID 存在但没有牌时按无牌处理。已有原牌的细节由后续解读提供，识别阶段无需用户重述。

纠正、解释原牌和有原牌的情绪支持不强制补牌。Agent 换题会去掉旧记录重新识别并开新回合；手动报告换题返回提问阶段，保留新问题而不使用旧牌解释。

首轮情绪支持当前仍在产品现有占卜流程中运行，使用支持式回答计划并禁止不被请求的行动建议；本轮未增加独立无牌聊天模式。普通追问仍保留原有补牌决策，不因 `reuseExistingCards: false` 强制补牌。

## 接口与数据

`POST /api/intent` 接受 `{ question, sceneId?, readingId?, previousIntentId? }`，直接返回 `IntentSnapshot`。首次问题最多 500 字，已有记录追问沿用 10000 字符限制。用户必须有有效会话；无效输入 400，不属于用户的记录 404，上下文失配 409，未启用、模型失败或非法输出 503。

快照包含版本、修订号、用户消息原文、场景、事实和约束、回答计划。事实/约束/目标必须引用具体消息中的非空原文；助手生成内容从不作为用户事实。`previousIntentId` 形成澄清修订链，所有读取按用户隔离。后续追问从所属初始及追问快照恢复用户原文链，避免仅保存最后一句澄清答复导致背景丢失。

客户端只向解读接口提交 `intentId`。服务端重新核对所属用户、当前问题、场景与记录绑定，拒绝尚需澄清的快照。初始和追问记录保存对应引用，聊天元数据记录版本和回答计划，重新解读沿用原快照。

历史记录仍使用原有 JSON 数据结构，新增可选 `intentId`、`sceneId`；旧记录和无意图引用的旧请求兼容。迁移不回填或改写旧数据。

## 提示词边界

固定策略放在 system 消息，用户原文、场景数据和经过校验的意图放在 user JSON 材料中。快照来源可信不意味着其中自由文本具有系统指令权限。当前默认提示词版本和 grounded 版本都可接入意图材料。自动选阵及补牌决策也读取完整材料，但使用独立决策提示词，保持原有 JSON 输出协议。

引用存在只能证明引用完整，不能证明模型正确理解原文。否定、时间、主观猜测、最新纠正和“不要建议”都有明确提取规则与协议测试；实际语义准确率仍须通过真实模型的人工标注评测衡量。

- 领域：`tests/intent.test.ts`。
- 服务端模型、鉴权与绑定：`tests/intent-server.test.ts`、`tests/intent-interpret.test.ts`、`tests/intent-reading-links.test.ts`、`tests/intent-decisions.test.ts`。
- 前端取消、竞态、澄清和换题：`tests/useIntent.test.tsx`、`tests/IntentGate.test.tsx`、`tests/AgentIntentGate.test.tsx`、`tests/ManualIntentRetry.test.tsx`。
- 数据库：`tests/intent-store.integration.test.ts` 默认跳过；仅在指定测试数据库并明确开启 `TAROT_DB_TEST=1` 时运行，测试创建独立 schema，不以正式数据库做验收。

以上 mock 测试不能替代供应商兼容性、真实延迟与语义质量验收。模型提取增加一次请求，其超时和输出预算复用现有设置，不承诺未经测量的准确率或响应时间。
