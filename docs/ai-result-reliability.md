# AI 解读结果与故障恢复

## 完成判断

浏览器和服务端通过 `lib/api/generation-result.ts` 共用判断。记录进行中为 `running`；结束后区分 `completed`、`truncated`、`interrupted`、`cancelled` 和 `no-valid-answer`。

- 仅有思考内容、空白、标点或空 Markdown 标题不算有效正文。
- 正常 `finish_reason: stop` 或 `[DONE]` 加有效正文才能完成。`length` 保留为截断；过滤、工具调用及未知结束原因不能完成文字解读。
- 未出现结束证据的 EOF 不算成功。已有正文保留，不自动调用模型重写。
- `persistenceStatus` 独立表示 `saved`、`failed` 或 `unknown`，不改变已确认的生成终态。历史保存接口会同步正文与终态，拒绝无正文的 `completed`。

`lib/tarot/sseUtils.ts` 在浏览器、代理和数据库记录器之间共用事件分帧，支持分包、多行 data、CRLF、无空格 data 字段和 EOF 尾帧。代理仅转发完整帧，心跳不会插入半截 JSON。客户端返回 `malformedEvents` 数量用于协议诊断，不包含用户内容。

## 请求预算和幂等

鉴权后的 `/api/interpret/config` 仅返回六个数值字段，模型地址和凭据仍留在服务端。每次请求读取运行时配置：

| 配置 | 行为 |
| --- | --- |
| `UPSTREAM_TIMEOUT_MS` | 上游连接预算 |
| `STREAM_CHUNK_TIMEOUT_MS` | 有效模型输出的最大间隔，以及最终保存等待预算 |
| `STREAM_HEARTBEAT_MS` | 下行心跳间隔及客户端回传余量 |
| `STREAM_TOTAL_TIMEOUT_MS`（可选） | 总生成预算，缺省由连接预算加输出间隔预算推导 |
| `STREAM_MAX_RETRIES`（可选） | 自动重试上限，缺省沿用原有 2 次 |
| `STREAM_RETRY_BASE_MS`（可选） | 指数退避基数，缺省沿用原有 1000 ms |

心跳和纯空白不会重置输出进度预算；持续输出也受总预算限制。客户端整次操作的预算覆盖所有尝试与退避。用户取消会传递到读取器和上游连接，取消、认证失败和非法请求不会自动重试。

一次 `streamInterpret` 调用生成一个 `operationId`，每次网络尝试有独立 `attemptId`。数据库按用户与操作加锁，并核对内容指纹：完成或已有正文的操作回放原结果，失败且无正文的操作复用原记录。不同内容复用标识及同一操作仍在进行时返回 409。旧尝试和旧 exchange 不能覆盖新结果。用户主动重新生成会创建新操作，保留原牌；重新抽牌仍走原有独立动作。

## 保存与恢复边界

增量数据库写入排队执行，不阻塞模型输出。最终保存等待有上限；等待失败后数据库可能稍后写入成功，因此页面保留正文并提示保存失败或未确认。

手动和 Agent 解读的保存重试通过现有存储接口补存正文与终态，不再调用模型。每日解读由服务端确定牌面，保存失败后按钮仅重新查询保存状态；没有开放让客户端任意写入每日 AI 结果的新接口。数据库持续不可用时，刷新页面可能丢失尚未保存的当前文本。

进程异常退出留下的 `pending` 操作不会自动抢占或再次生成，以避免重复调用；用户可以查看历史或主动发起新操作。旧历史没有结束证据时保留“无法确认完成”的提示，不补造成功记录。

## 输出质量

决策仅接受正式正文中的完整 JSON（允许完整 JSON 代码块），校验牌阵 ID、决策枚举和抽牌数。格式或临时失败使用明确标记的默认方案；认证和取消错误向上传递。

质量规则区分首轮、直接追问、补牌和每日解读。缺章节、无法识别的牌位格式只警告；明确的牌名、牌位和正逆位冲突提示保留原牌重新生成，保留原文供核对。规则不会修改实际抽牌，也不会自动追加 AI 修复请求。

离线固定语料、语义复核维度与运行方式见 [解读质量评估](./interpretation-quality-evaluation.md)。确定性规则只能验证结构和明确牌面声明，不能证明模型对现实事实、他人心理或建议的判断正确。
