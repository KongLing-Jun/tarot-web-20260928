# 微信小程序 web-view 接入

小程序承载现有网站并负责微信登录：`wx.login` → 服务端验证 → 一次性票据 → web-view 网站首页。React 页面、CSS、牌图、抽牌逻辑、数据库历史和 `/api/*` 全部继续由网站提供，无需转换成 WXML/WXSS，也无需安装小程序 npm 依赖。

## 本地联调

1. 在项目根目录执行 `npm install`，按 [数据库与登录说明](./DATABASE.md) 填写 `model.config.json` 中的数据库连接、微信 AppID 和 AppSecret，运行 `npm run db:migrate`，然后执行 `npm run dev:miniapp`（监听地址和端口由 `MINIAPP_DEV_HOST` / `MINIAPP_DEV_PORT` 决定，见[后端配置](./CONFIG.md)）。
2. 微信开发者工具导入当前项目根目录（含 `project.config.json` 的目录）。根目录 `project.config.json` 已保留原 AppID，并通过 `miniprogramRoot` 指向 `miniprogram/`。
3. 开发版打开 `miniprogram/config.js` 中的 `develop` 地址；需与本机实际监听端口和电脑可访问地址匹配。在开发者工具的「详情 → 本地设置」中，仅在本地联调时勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。个人工具设置保存在已忽略的 `project.private.config.json`。
4. 点击编译。网页内部导航继续使用原有链接；无需为每日一牌、对话、占卜、图鉴和历史各建一个原生页面。

手机不能使用电脑的 `localhost`。手机联调时，将 `miniprogram/config.js` 的 `develop` 改为电脑局域网地址（例如 `http://192.168.1.20:3001`），让电脑和手机处在同一网络并确保防火墙允许该端口；本地 HTTP 调试需要客户端支持并开启对应调试设置。更接近发布环境的方式是使用已配置业务域名的 HTTPS 测试站点。工具中关闭校验不会让体验版或正式版获得域名权限。

## 体验版和正式版

### 本地复现体验版的域名限制

1. 将 `miniprogram/config.js` 的 `develop` 和 `trial` 配置成同一个线上 HTTPS 站点。此时本地小程序访问线上网页及后端，本地 Next.js 页面改动不会自动同步到线上。
2. 项目默认启用 `setting.urlCheck: true`，本机 `project.private.config.json` 中也需保持为 `true`（私有配置优先级更高）。关闭并重新打开微信开发者工具中的项目，在「详情 → 本地设置」确认**未勾选**「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」，再重新编译。
3. 在当前 AppID 对应的微信后台确认已配置该站点的 request 合法域名及业务域名；更改后台配置后，在工具的「详情 → 开发设置」刷新域名配置，并重新编译查看 Console 的具体错误。
4. 本地运行仍是 `develop`，无需伪造 `envVersion`。这些设置只对齐访问地址和开启工具校验，不能赋予主体 web-view 权限，也不能完全模拟手机微信；最后仍需用关闭调试模式的真机体验版验证。

参考：[微信开发者工具项目配置](https://developers.weixin.qq.com/miniprogram/dev/devtools/projectconfig.html)。

`miniprogram/config.js` 根据微信的 `envVersion` 选择地址：

| 配置 | 用途 | 配置说明 |
| --- | --- | --- |
| `develop` | 开发调试 | 以 `miniprogram/config.js` 为准；手机使用电脑局域网地址，工具本机联调可使用 localhost |
| `trial` | 体验版 | 待填写 HTTPS 测试站点 |
| `release` | 正式版 | 待填写 HTTPS 正式站点 |

填写站点源地址即可，例如 `https://tarot.example.com`，不要添加页面路径、查询参数或密钥。体验版和正式版不会回退到本地开发地址；未配置时会显示「网页暂未开放」，开发者工具控制台会给出具体原因。

1. 将现有 Next.js 应用部署到可用的 HTTPS 域名，执行 `npm run build` 和 `npm run start`。应用包含服务端 API，不能只上传静态 HTML，也不能改成静态导出。
2. 在服务端项目根目录配置私有 `model.config.json`，保持现有 AI 接口可用。网站页面和 `/api/*` 使用同一个域名；反向代理需要支持流式响应，避免对 `/api/interpret` 缓冲，并设置足够的请求超时。代理必须保留浏览器访问的 `Host`（含非默认端口），并覆盖 `X-Forwarded-Proto` 为实际访问协议，确保来源校验正确识别外部 HTTPS 地址。
3. 在微信小程序管理后台配置该站点的**业务域名**和 **request 合法域名**（登录通过 `wx.request` 调用站点 API）。后台如要求域名校验文件，将原文件放进 Next.js 的 `public/` 并部署，确保域名根路径可以直接访问该文件。
4. 填写 `trial` 和 `release` 后，在开启域名校验的条件下验证体验版，再上传发布。

使用前请确认小程序主体拥有 `web-view` 和业务域名权限；个人主体通常无法使用这条接入路线。实际资格、域名及备案条件以微信后台为准。参考 [微信 web-view 文档](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html) 和 [项目配置文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/projectconfig.html)。

## 界面与数据

- 网站保持原有暗色主题、字体、动效和移动端布局。补充了 viewport 安全区设置及底部导航、对话输入区的安全区间距。
- 微信原生顶部导航栏使用相同背景色；`web-view` 自身铺满可用页面，顶部系统栏仍由微信控制。
- 加载失败会移除 `web-view`，显示原生提示和「重新加载」按钮。分享卡片统一打开首页，不携带问题或本地历史详情。
- 聊天和占卜历史保存在 PostgreSQL，按微信用户隔离；同一小程序账号在不同设备登录后可读取自己的历史。首次登录自动创建用户 ID、默认昵称和默认头像。旧 localStorage 历史不自动迁移；每日牌、札记与解读按账号保存在数据库，旧设备札记可由每日页明确导入，见[存储说明](./DATABASE.md)。
- 小程序上传目录仅为 `miniprogram/`；Next.js 源码、`node_modules` 和服务端密钥不在该目录中。不要将密钥放入小程序配置或网站 URL。

## 手机抽牌手势

手势作用于网页牌堆视窗，微信原生导航不参与缩放。

| 操作 | 结果 |
| --- | --- |
| 单指沿牌弧滑动 | 依次预选，附近牌柔和散开并抬起；牌堆整体与视野稳定，放大后仍可拨牌 |
| 双指捏合或张开 | 围绕双指中点缩放牌堆，范围 75%—200%；不改变已抽牌与牌序 |
| 双指同向移动 | 移动牌堆视野；双指接管会取消正在进行的单指抽取 |
| 沿当前牌向扇形外侧拖出 | 浮层显示抽取反馈，达到距离后松手确认并在牌堆留空；短拖、拖回和取消不抽取 |
| 底部“抽取这张” | 提交当前预选，与拖出操作使用同一确认流程；最后一张确认后自动进入未揭开的揭牌页 |
| “撤回上一张” | 归还最后一个已选牌位的原牌；未抽牌时禁用 |
| 上一张 / 下一张、方向键、Home / End | 精确选牌并将目标带入视野；键盘 + / - 调整大小，0 恢复 |

选牌页不再展示顶部牌位区和飞入牌位动画，完整半圆环以默认 100% 比例紧接进度提示。页面不显示放大、缩小或恢复大小按钮；牌堆之外保留页面正常滚动。揭牌前可以“返回调整”，满额时使用“返回揭牌”，撤回并补选完成后自动进入揭牌；首次揭牌才保存记录。当前变更及验证边界见[牌堆主视觉调整](./tasks/fan-stage-20260911.md)，历史触控验收文字记录见[手势验收](./design-qa.md)。

## 登录生命周期与开发者工具错误

原生页面每次登录使用独立尝试标识。页面卸载时先使回调失效，再取消在途 wx.request；延迟 wx.login 回调和 web-view 的 load / error 事件不会继续更新已卸载页面。重新进入后正常登录，错误页仍支持重试，回到原网页的路径保持不变。

用户报告的 Cannot read property '__subPageFrameEndTime__' of null 已定位到本机基础库 3.17.3 的渲染上下文定时器；同机 3.16.2 / 3.17.2 也存在相同形式的轮询。项目卸载竞态有回归测试证明并已修复，但原始基础库异常的完整触发链尚未复现，不能仅凭项目测试通过断言该异常完全消失。

本轮已通过微信官方 CLI 清理编译缓存并关闭、重新打开项目，没有清除登录和业务缓存。再次遇到相同错误时，应记录基础库与工具版本、首次启动还是保存重编译触发、是否也影响真机，再按原场景复测。源码证据、恢复范围和限制见[错误排查记录](./tasks/wechat-frame-recovery-20260911.md)。

## 验收

先运行 `npm run lint`、`npm test` 和 `npm run build`。再在微信开发者工具和真机检查：

1. 首页、对话、每日一牌、占卜、图鉴及历史页可以打开，图片和样式正常。
2. 单指沿弧拨牌、双指缩放与平移、向外拖出和底部按钮均可抽取；短拖、回拖、双指接管与取消不会误抽。流式解读、追问和取消可用，历史在关闭并重新进入后仍能读取。
3. 底部导航和输入框不被手机安全区遮挡，键盘弹出、收起和页面返回正常。
4. 停止网站并重新编译，确认出现重试界面；恢复网站后点击重新加载。
5. 登录中离开、关闭或重新编译后重新进入，确认旧回调不会恢复旧页面；按原始步骤检查基础库空指针是否重现。
6. 体验版和正式版使用配置的 HTTPS 站点，分享后进入首页。

自动化检查不替代微信客户端的加载、业务域名校验、流式响应和键盘真机验证。

当前布局与验证批次见[牌堆主视觉调整](./tasks/fan-stage-20260911.md)；此前主分支合并结果见[集成记录](./tasks/integration-20260911.md)。上述真机清单尚未全部执行，不能据此视为发布验收通过。
