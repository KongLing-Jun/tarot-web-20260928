# 用户意图识别执行计划

状态：代码实现及本地验证完成；真实数据库迁移、模型验收与开关启用未执行。用户已批准在本目录另存计划并实施，不覆盖 tasks/ 下原有狐狸主题计划。

## 目标

在现有场景占卜和 Agent 入口增加可验证的服务端意图识别：提取带原文依据的事实、目标和约束；缺少决定性信息时先提出一个澄清问题；用户修改问题或纠正事实后生成新版本；将服务端回答计划与用户材料分离注入解读。保持页面 URL、抽牌结果、现有记录和旧客户端兼容。

## 架构决策

- 用固定协议连接领域校验、服务端识别与前端交互。模型输出视为不可信数据；结构、枚举、引用和所属用户由代码校验。
- 使用现有服务端模型配置、超时和输出预算，不增加私钥或客户端模型凭据。
- 新建用户隔离的意图快照表，保存源消息、版本和计划。快照不可变；引用 ID 必须与当前问题、场景及记录归属匹配。
- 场景是提示，不覆盖用户最新明确目标；用户陈述与模型假设分离。历史从服务端所属记录读取，不接受客户端伪造历史。
- 前端在抽牌/生成之前识别，显示澄清或可重试错误；编辑问题使进行中的识别失效。识别失败不得自动当作成功。
- 解读使用服务端已校验快照，客户端不能上传任意 system prompt。旧请求缺少 intentId 时保持原路径，便于现有记录兼容；启用开关后的新入口先识别。
- 不根据模型自报置信度设置武断阈值；第一版采用证据、缺失项和明确约束决策。不进行自动依赖升级、生产部署或真实付费模型验收。

## 依赖与执行顺序

1. 领域协议、证据校验、场景策略及回答计划。
2. 数据迁移、用户隔离存储、模型提取和 /api/intent 接口。
3. 提问界面识别与澄清闭环，接入手动和 Agent。
4. 解读注入、历史关联及追问纠正。
5. 回归、浏览器模拟验收、文档与交付。

领域与服务端在协议明确后并行；前端识别 Hook 可以独立实现。共享流程接入由主任务统一修改。

## 验收与风险

- 纠正优先、否定和时间表达、只倾诉、二选一缺选项、无依据引用等均有测试。
- 401/400/404/409/503、跨用户访问、过期问题引用、取消/编辑竞态、模型不合法输出均有覆盖。
- 不以格式正确证明语义正确；模型理解质量需要标注样本和真实模型评测，交付明确未实测项。
- 新迁移只增加表及必要索引，不改写旧占卜数据；配置若连接生产库，不自动迁移真实数据库。
- 完成后运行定向测试、全量 Vitest、TypeScript、ESLint、Prettier 与构建，恢复原本本地服务。
